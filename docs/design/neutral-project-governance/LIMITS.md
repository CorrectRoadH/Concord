# 约束

## L1: 不强迫技术栈或纯文档目标

不以纯文档项目作为设计目标，不强迫消费者采用 Concord 开发栈。来源：原设计约束。判定依据是候选的接入协议不得要求消费者技术栈迁移。

## L2: 保留编辑并禁止外部副作用

保留已有 Web 未提交编辑；不发布、push、远端 mutation 或付费调用。来源：原设计约束。判定依据是候选和验收不得扩大外部操作。

## L3: 证据类型与旧原件不可降级

不把 command evidence 当作 native/reliability 证明；旧原件不能通过改字段重签。来源：原设计约束。判定依据是证据校验是否保持类型和历史边界。

## L4: 身份绑定与 red/green 候选规则

源码/helper、契约、policy、配置和 adapter 身份必须绑定。red 允许使用不同的缺陷候选，green/reliability 必须使用同一修复候选。来源：原设计约束。判定依据是候选是否表达这些身份与候选选择规则。

## L5: fixed 门槛与迁移保护统一

跨入口 fixed 使用共同最低要求；迁移共同保护旧、新锁和未完成事务。来源：原设计约束。判定依据是候选是否统一 fixed 门槛并保留跨旧新锁的停写切换。
