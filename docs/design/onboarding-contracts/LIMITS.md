# 初始化配置与项目治理契约

## L1: 本地独立且无外部副作用

保持本地独立安装，不依赖外部 checkout、付费模型或远端 mutation。来源：原设计约束。判定依据是隔离打包消费者和无外部副作用边界。

## L2: 保留消费者现场与身份

保留既有消费者、未知工作区改动和现有 Memory 历史；不可静默改写引用身份。来源：原设计约束。判定依据是完整前像、canonical identity 和恢复规则。

## L3: 配置与恢复协议一致且查询不执行脚本

配置入口、读取、编辑、证据及恢复使用一致协议，普通查询不能暗中执行消费者脚本。来源：原设计约束。判定依据是静态配置读取、快照和恢复行为。

## L4: 宪法必需且不冒充证据

新项目宪法必需，DESIGN.md 可选；规则内容不冒充实现证据。来源：原设计约束。判定依据是初始化产物和 review/check 语义。

## L5: 不实现远端 provider 或跨后端同步

本轮不实现远端 provider 或跨后端自动同步。来源：原设计约束。判定依据是候选范围不扩大到远端同步。

## L6: 严格工程栈与隔离验收

严格 TypeScript、Effect 与固定依赖，公开验收使用隔离打包消费者。来源：原设计约束。判定依据是实现和验收契约，而不是文档结构检查。
