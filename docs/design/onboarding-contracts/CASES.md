# 初始化配置与项目治理契约

| Case ID | 用户问题 | 固定输入 | 验收结果 |
|---|---|---|---|
| C1 | 初始化可取消 | 空 Git 消费仓库，交互取消或 dry-run | 不留下文件或私有事务状态 |
| C2 | 组合项目特点 | Library 与 CLI，同时关闭 DESIGN.md | 宪法存在，默认页面组合正确，无 DESIGN.md |
| C3 | 旧项目继续使用 | 既有 JSON、Memory 引用与历史 | 可读取且无隐式迁移，恢复仍可用 |
| C4 | 配置安全 | 双配置、非法 TS 表达式、写入中断 | 明确拒绝或按既定 journal 恢复，不执行隐藏副作用 |
| C5 | 多来源有实际行为 | 两个来源含相同短 id，其中一个只读 | 可辨来源，歧义和非法写入明确报告 |
| C6 | 新规则影响已有功能 | 引用旧条款的功能，随后修订宪法 | 当前规则与修订影响可见，不声称自动合规 |
| C7 | 默认值可覆盖 | 项目有默认页面，单次明确仅 README | 只建 README，已有文档不被修改 |
