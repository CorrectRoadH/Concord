# 契约写法与源码关联

## Decision

Undecided.

作者推荐 behavior-anchored，等待独立审查后定案。

## Rationale

behavior-anchored 满足全部 Limit，并让写法与关联规则成为可以在审阅中引用的硬约束。wording-only 同样满足 Limit，但规则停留在建议层面，代码关联仍没有宪法依据。

G3: 规则要求最窄范围，但没有工具提示粗粒度声明。接受这个缺口，因为提示能力会改变 `trace gaps` 的公开输出，需要单独的 Design；在此之前由作者与审阅执行，自举仓库的文件级声明逐步改写。

## Rejected Options

wording-only：G1、G2、G4 只能部分满足，G3 不满足。写作指南不是接入项目必须遵守的规则，C-011 也不覆盖代码声明。

## Residual Risks

- 现有行为页与代码声明大量不符合新规则，修订后存在一段规则与现状不一致的时期。按 C-008.3，宪法不声称现状合规；逐页改写由文档工作承担，代码声明由实现任务改写。
- “最窄范围”需要判断。C7 与 C8 给出了允许较粗粒度的情形，其余情形由审阅判断。
