# 行为锚定：重写 C-011 与 C-012

## Problem

C-011 与 C-012 需要直接给出“写什么、写在哪、关联到哪”的规则，而不是只划出禁止项。

## Core Mental Model

C-012 拥有契约写法：行为页写可观察行为，architecture 与 lifecycle 页写实现，过程不进入契约。C-011 拥有关联：测试与代码标记都指向它们验证或实现的最窄行为 anchor。C-012 中与写法无关的三款移到更合适的条款。

### C-011 修订正文

> ## C-011 关联由源码标记拥有，指向最窄的行为
>
> 1. 测试与实现源码中的 Concord 标记是关联的唯一正向来源，标记存在即关联存在。反向关系从标记派生。静态关联扫描不解析宿主语言的测试声明、框架绑定、回调或 skip/todo。
> 2. 测试标记指向它验证的行为：Use Case、Use Case 步骤，或行为页的标题 anchor。只验证内部不变量的测试可以指向 architecture 或 lifecycle 页的 anchor；对使用者可观察的保证先写进行为页，再让测试指向它。
> 3. 实现标记指向它实现的行为，并选择两端都最窄的范围：代码侧优先使用函数或语句区域，只有整个文件服务同一份契约时才使用文件级声明；契约侧优先使用步骤或标题 anchor，只有代码服务整份契约时才指向 README。
> 4. JS/TS 仅用注释范围排除字符串和模板中的伪标记；其它文本文件接受以 `//`、`#` 或 `--` 开头的标记行。
> 5. 执行由接入项目的 runner 命令或显式配置的 adapter 负责。（原第 3 款全文保留。）

### C-012 修订正文

> ## C-012 契约写可观察行为，实现与过程各归其位
>
> 1. 行为页（Feature README、Use Case、cli、library）用使用者的语言声明输入、可观察结果、错误与约束。每条陈述都能被测试断言：命令与 API 页给出完整调用、人读与机器可读输出、退出码、具名错误和最小示例，示例取自真实运行。行为页不写模块名、数据结构、调用链或存储引擎。
> 2. architecture 与 lifecycle 页声明该 Feature 的实现：实体归属、数据流、不变量、失败阶段与资源生命周期。它们随实现修改，不重新定义行为。跨 Feature 的系统边界写在项目 `docs/architecture.md`。只改实现的修改不改行为页。
> 3. Roadmap 与 Feature 同体裁，表示尚未采用的方向。实现与测试不指向 Roadmap。
> 4. 约束用现行句式表达，只描述当前规则，不描述与过去的差别，不点名已删除的接口、实现或文档。
> 5. 实施日志、进度、待办、排障经过、测试运行记录、审阅经过、提交收据和 agent 交接不进入 `docs/`。排障经过、根因与经验归 Memory，待调查的观察归 Issue，正式采用的目标归契约。Research、Design 与工具维护的元数据由各自 owner 保留，本规则不授权删除或改写既有证据、来源及生命周期历史。

### 移出 C-012 的条款

| 原条款 | 新位置 | 理由 |
| --- | --- | --- |
| C-012.4 Memory/Issue 只经工具维护 | C-001 第 5 款 | 这是 owner 完整性规则，与契约写法无关 |
| C-012.5 本地 Issue 不依赖外部服务 | C-002 第 2 款末句 | 这是本地独立性规则 |
| C-012.6 凭据不落盘 | C-007 第 4 款 | 这是外部授权与安全规则 |

## Scope

- 改写 C-001、C-002、C-007、C-011、C-012 的正文，anchor 不变。C-010 第 1 款对 C-012 的引用保持有效。
- 同步修改随包 skill（`concord --skill` 与 `document`、`code`、`test` 主题）、`docs/concord.md` 与 init 生成的指引，使 Agent 读到同一套规则。
- 不改变 CLI 行为、标记语法或 JSON 字段。
