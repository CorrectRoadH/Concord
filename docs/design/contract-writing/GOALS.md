# 契约写法与源码关联

## G1: 不看代码也能判断行为

读者只读行为页，就能知道一个功能接受什么输入、产生什么可观察结果、在什么情况下以什么错误失败。判定方法：对 CASES 中的 C1，读者能写出断言而不需要打开源码。

## G2: 重构不改行为页和指向行为的测试关联

只改变内部实现、不改变可观察行为的修改，只需要更新 architecture 或 lifecycle 页；行为页与指向行为契约的测试关联不变。判定方法：CASES 中的 C3。

## G3: 关联能回答“哪段代码实现了哪一步”

从 Use Case 的一个步骤能找到实现它的代码范围和验证它的测试；从一段代码能找到它服务的步骤。判定方法：CASES 中的 C4 与 C5。

## G4: 规则对人和 Agent 同样可执行

规则用可以逐条检查的句子写出，Agent 读 `concord --skill` 就能照做，不依赖对话上下文。判定方法：CASES 中的 C6。

## G5: 规则约束所有接入项目

行为页与实现页的分工、关联范围的选择适用于每个接入项目，审阅可以引用一条范式规则判定违反。判定方法：审阅者能对 C2 与 C7 的违反引用一条宪法条款。
