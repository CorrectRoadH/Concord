# 测试关联到 Use Case 步骤

| 场景 | 输入与操作 | 验收结果 |
| --- | --- | --- |
| C1 | 不同语言章节下的顶层有序项带 `{#reject-token}` | 指向步骤的关联可导航；章节名称不影响步骤集合 |
| C2 | 引用已有标题、整个 Use Case、缺失 ID | 前两者保留且分组展示；缺失 ID 产生引用 finding |
| C3 | 步骤 ID 与标题显式 ID、slug 或折叠连字符别名冲突 | `DuplicateAnchor`，不能任意选择目标 |
| C4 | 改步骤文字、插入或移动其它项 | 步骤引用保持不变；ordinal 仅随展示顺序变化 |
| C5 | 三个步骤只有两个有测试标记 | 展示未关联步骤；check 不因此失败 |
| C6 | 直接调用样本的依赖观察匹配同一步骤声明 | `observed`，level 为 step，公开匹配与范围 |
| C7 | 文件中另一 case 导入声明、辅助函数转调或只有其它 Feature 声明 | 不冒充该 case 的行为证明；无目标交集时 `not-observed` 并列 gaps |
| C8 | 打包 CLI 子进程、HTTP 边界、没有分析器或达到闭包上限 | `not-observed`，给出边界或上限原因 |
| C9 | 同文件带 `@name` 的标记从文件改为步骤目标 | v1 ID 可保持；定义摘要变更，旧收据不能复用 |
| C10 | 没有步骤或只有非步骤标题关联 | 文件与标题引用继续有效，无步骤不产生 finding |
| C11 | fence、行内代码、HTML 示例含 `{#id}` | 不生成步骤；无序项、嵌套项或 supporting page 的真实步骤语法产生 `InvalidStepPosition` |
| C12 | 验收列表不带步骤标记；另有合法顶层标记位于任意章节 | 未标记项不进入步骤视图；合法顶层标记均按步骤解析，章节名称不隐式改变规则 |
| C13 | 同一源码冷缓存、热缓存、损坏缓存与清空缓存 | check 当前关系、finding、退出码和 complete 一致；观察展示可有时效差异 |
| C14 | 错误原生标签且没有 Concord 标记 | 标签不产生关联；错误源码标记始终被 check 发现 |
| C15 | 构建打包后的 CLI 在隔离 Git 消费者读取正误标签样本 | 导航与观察分别验收；不以收据数量代替行为验证 |
| C16 | 主流程三项中两项有 ID，运行 `use-case format` | 只给缺失项补 `step-N`，已有 ID 与顺序不变 |
| C17 | 无 ID 的主流程列表与验收列表并存 | 默认 format 零写入；`--seed --list` 只标记显式选中的列表，其它列表不变；选择缺失或前像变化时拒绝 |
| C18 | `rename-step` 把 `step-2` 改为 `拒绝过期令牌`，测试、代码与文档链接都引用它 | 一个变更集改写全部精确引用；JS/TS 字符串与 Markdown 代码示例中的相同文本不变；列出受影响 case |
| C19 | 规划完成后、提交前修改任一输入；分别在首个文件发布后和 committed journal 持久化后中断，再由第二个 CLI 读取、发布与恢复 | 提交前冲突零写入；未完成现场被阻断，prepared 安全回滚，committed 保留结果；出现未知编辑时恢复拒绝并保留现场 |
| C21 | 删除或改名最大序号 `step-3` 后运行 format；标题已占用下一序号；旧引用仍指向被删除的 ID；连续运行两次 format | 不分配被标题或旧引用占用的 ID；引用扫描不完整时拒绝；第二次 format 零写入 |
| C20 | 旧引用出现在 Design decision 或 Memory promotion 中 | `ManagedReferenceBlocked`，零写入 |
