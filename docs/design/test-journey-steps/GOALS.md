# 测试关联到 Use Case 步骤

## G1: 测试可以指向单个步骤

测试与代码标记可以指向共同契约定义的步骤。导航按步骤聚合关联，保留整个 Use Case 和非步骤标题的关联。

## G2: 没有测试的步骤可以被发现

视图列出未声明测试关联的步骤。该状态不产生门禁失败，不是覆盖率。

## G3: 观察测试依赖与声明的交集

视图报告 `observed` 的匹配声明与层级，或 `not-observed` 和 gaps。文件范围观察不能冒充逐原生用例的行为证明。

## G4: 契约正文保持可读

步骤保持连续有序列表，不要求固定语言的章节标题。比较额外导航的阅读成本。

## G5: 步骤身份在普通编辑下稳定

改文字、插入或移动其它步骤不改变显式 ID。删除或重命名 ID 要求作者修复引用。

## G6: 步骤 ID 的书写与维护成本低

作者可以用正文所用语言命名步骤，由工具补齐缺失 ID，并用一个命令改名且同步全部引用。判定依据是候选是否提供补齐与原子改名，以及改名是否覆盖源码标记与文档链接。
