# 共同身份与观察结果

本页是 [test-journey-steps](README.md)、[test-adapters](../test-adapters/README.md)、[lsp-integration](../lsp-integration/README.md) 与 [controlled-writing](../controlled-writing/README.md) 共同遵守的契约。四份 Design 的候选只能引用本页，不重新定义下列身份与语义。

## 四种身份

| 身份 | 形式 | owner | 能否由缓存改变 |
| --- | --- | --- | --- |
| 步骤 | `<use-case path>#<step-id>` | Use Case 正文 | 不能 |
| 测试关联 | 现有 `concord.test-reference/v1`：文件加 `@name`，或文件加契约目标与序号 | 测试源码标记 | 不能 |
| 代码关联 | 现有派生代码引用；非 TypeScript 文件为文件路径加标记块序号 | 代码声明 | 不能 |
| 原生选择 | adapter 观察到的原生 ID 集合 | 无，执行时观察 | 只影响执行与收据 |

- 测试关联 ID 保持 v1 派生规则，不升级版本。带 `@name` 的标记改变契约目标时 ID 不变；旧收据因 annotation 与 contract 摘要改变而不能用于新目标。
- 原生选择不进入测试关联 ID。是否存在原生清单，不改变 case 集合、case ID 或 `check` 的关系结论。
- 原生标签（pytest mark、JUnit Tag 等）不是关联来源。关联只来自 `@feature` 与 `@use-case` 标记。

## 步骤语法

- 步骤是 Use Case 正文中顶层有序列表项，第一段末尾带 `{#id}`，前面至少一个空格。没有 `{#id}` 的有序列表项不是步骤。
- 识别不依赖章节标题文字。`{#id}` 出现在无序列表项、嵌套列表项、Feature 或 supporting page 中时，`check` 产生 `InvalidStepPosition`。
- ID 语法为 `[A-Za-z][A-Za-z0-9_.:-]*`，与同一文件的标题 anchor 共用命名空间。冲突检测同时比较标题的显式 ID、slug 和折叠连字符后的别名，冲突产生 `DuplicateAnchor`。
- 代码 fence、行内代码与 HTML 中的 `{#id}` 不是步骤。
- `@use-case <path>#<anchor>` 继续接受任意已存在的标题 anchor，现有引用不失效。步骤视图只把指向步骤的关联归入该步骤，其它 anchor 关联归入"非步骤 anchor"。
- 验收条目不是步骤，不提供条款身份。

## 观察结果

原生清单、LSP 分析快照与相关性判定都使用同一结构：

```ts
interface Observation<T> {
  readonly value: T;
  readonly inputs: string;          // 全部实际输入的摘要，含实现与版本
  readonly complete: boolean;
  readonly gaps: readonly string[]; // complete 为 false 时的具名原因
  readonly observedAt: string;
  readonly current: boolean;        // 输入摘要与当前源码一致
}
```

- 观察结果只进入 HawDB，可丢弃。`check` 的退出码、finding 与 `complete` 不读取观察结果。冷缓存、热缓存、缓存损坏与清空后，`check` 的关系结论相同。
- `current` 为 false 的观察结果只作历史展示，标明来源与时间，不用于选择执行或判定。
- 只有显式命令产生观察：`test collect`、`code analyze`，以及 `test run` 对目标的执行前收集。静态命令与编辑器服务只读取。

## 相关性判定

相关性判定只报告观察到的事实，不输出"无关"结论。

| 结果 | 含义 |
| --- | --- |
| `observed` | 测试的依赖中观察到声明实现目标的代码；带 `level`：`step`、`use-case` 或 `feature` |
| `not-observed` | 没有观察到这样的代码；总是带 `gaps`，例如 `FileScope`、`DepthLimit`、`NoSourceImports`、`SubprocessBoundary`、`NoAnalyzer`、`SnapshotNotCurrent` |

- `not-observed` 不表示测试与契约无关。CLI、review 与工作台的文字必须写成"未观察到交集"并列出原因。
- 判定不产生 finding，不改变退出码。

## 原生执行收据

使用 adapter 时，收据记录 `requested`（选中的原生 ID）与 `observed`（报告中的每项结果）。

- green：`requested` 非空，每个 ID 在报告中恰好出现一次且为 `passed`，命令退出 0，进程清理完成。
- red：`requested` 每个 ID 都恰好出现一次，至少一个为 `failed`，命令非零退出，进程清理完成。adapter 解析失败、报告缺失或基础设施失败不是 red。
- 其它情况：缺失、重复、额外 ID、`skipped`、截断、超时与清理未知，收据结论为 `invalid`，不能用于 fixed。
- 收据格式增加版本号；旧收据保留原件，不重算摘要，需要时重新取证。逐用例结果不自动满足 [repository profile](../../repository-profile.md) 的原生可靠性要求。
