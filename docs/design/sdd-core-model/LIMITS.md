# 以 Spec 驱动开发的核心模型

## L1: 只有当前格式

不提供迁移命令、兼容读取或双轨模型；本仓库与接入项目直接改写为新格式（[C-009](../../constitution.md#c-009-1)）。

## L2: 修复经过核验且可审计

缺陷标记为已修复之前，同一测试必须在明确的缺陷候选上失败、在修复候选上通过（[C-004](../../constitution.md#c-004)）。核验结论在仓库中可审计；在声明的输入与运行环境可获得时可以重放。缺测试、无法构建与基础设施失败是无法核验，不是失败。

## L3: 工具写入保护前像

Concord 执行的写入继续使用整文件摘要与 publication 协议，不覆盖外部编辑（[C-003](../../constitution.md#c-003)）。

## L4: 关系从来源派生

反向关系与索引从文件和标记派生，不维护第二份登记表（[C-001](../../constitution.md#c-001-3)）。

## L5: 声明式文档只写当前

Spec 与项目规则只声明当前，不保存创建时间与修订历史（[C-012](../../constitution.md#c-012-11)）。

## L6: 不重复保存可推导的事实

能从路径、一级标题或其它 owner 推导的字段不再保存；空数组与空对象不序列化。

## L7: 只有当前格式

与 L1 相同，列为用户约束：改写一次到位，不保留双轨。
