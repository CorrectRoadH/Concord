# 以 Spec 驱动开发的核心模型

## G1: 每个事实只声明一次

身份、类别、所属关系与标题不在路径、标题和元数据中重复声明；Spec 文档不需要 frontmatter。判据：任一事实只有一个声明位置，改名只需移动文件。

## G2: 分类少而不重叠

文档类别不超过五类（Spec、项目规则、决策记录、工作项、知识），任意两类回答的问题不同；同一件事（未实现的方向、缺陷、决策）只有一个归属。

## G3: 编辑 Spec 不需要专用命令

人与 agent 用编辑器直接修改 Markdown 即可完成 Spec、决策与知识的维护；Concord 的写命令只用于需要证据核验的状态转换与脚手架。CLI 顶层子命令不超过 12 个。

## G4: 零配置可用

只有 `docs/` 的仓库无需配置即可运行 `concord check` 与 `trace`；配置只表达项目确实需要选择的内容。

## G5: 检查不变弱

放置错误、悬空链接、未定义概念、缺少测试的 Use Case、无证据的修复关闭，仍由检查器报告。
