# 以 Spec 驱动开发的核心模型

用户的明确偏好列为约束（见 [Limits](LIMITS.md) L5–L7）；本页的目标按维护效果比较。

## G1: 重复声明最少

统计每个 owner 中能从路径、一级标题或其它 owner 推导的字段数，以及改名、移动时需要同步修改的位置数。越少越好。

## G2: 每件事只有一个归属

未采用的方向、已采用的能力、缺陷、决策、可复用知识各有唯一归属；同一事实不会出现在两类文档中。

## G3: 日常维护的步骤少

新增 Feature、修改验收、修复缺陷、记录经验、采用方向、裁决设计这六个动作，每个所需的命令与手工步骤数；以及公开 CLI 的全部顶层命令数。

## G4: 零配置可用

只有 `docs/` 的仓库无需配置即可运行 `check` 与 `trace`；配置只表达真实选择，可选覆盖不计为负担。

## G5: 检查与保证不变弱

放置、关系、概念、缺测试的 Use Case、修复核验、写入授权与采用授权的现有保证，除非在本设计中逐项明确放弃并修订宪法，否则全部保留。
