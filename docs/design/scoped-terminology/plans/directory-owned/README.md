## Binding resolutions of the six challenge conditions

These rules supersede ambiguous earlier proposal text.

1. Selection and application are separate. Default project scan selects the union of roots of every discovered policy (omitted roots -> containing scope, global -> docs) and each catalog directory that has NO colocated policy (global -> docs). Thus local owners can start scans outside a narrow global selection; local scope may not reach outside its directory. Within selected files every global/ancestor policy applies regardless of which owner selected the file. Policy roots only select files; per-ban roots/exempt restrict a particular rule. Local roots never cancel ancestor rules. An empty catalog with no policy selects its folder; an empty directory with no readable document yields a named no-input error, not false success. Explicit managed --rules/path selects ONLY that policy's roots but composes all applicable discovered policies/catalogs on selected files, including descendants on those files; it does not expand the selection to other scopes. Explicit non-managed --rules is a standalone read-only profile: select its roots/default docs, use only its policy plus scoped catalogs; no discovered policy composition. Reports expose mode and selected roots. Catalog-only repo works; no sources anywhere -> WritingPolicyNotFound.

2. ASCII whole spellings normalize case-insensitively and use word boundaries; non-ASCII spellings exact literal. Use the identical normalization/matcher for alias validation, effective name collisions and rule checks; no locale-dependent implicit behavior. Canonical concept reference deduplicates inheritance/import paths. Conflict detection uses actual selected-file applicability, including ban roots/exempt/allowIn. Disjoint exemptions/scopes do not conflict. For any actual occurrence whose applicable constraints disagree on normalized preferred output, or forbid an active preferred/alias spelling of a different applicable concept, emit a sourced conflict and no arbitrary replacement. Two different effective concepts owning same normalized preferred/alias is likewise an ambiguity diagnostic in their overlapping scope (retain both refs; no implicit override). Compatible bans may deduplicate each (file,location,normalized term,replacement), but MUST retain all source refs and evaluate each original rule's exemptions first. Same-source duplicate manual terms can remain rejected. Catalog aliases are never implicit bans. Optional numeric length thresholds accept null to explicitly clear inheritance; absent inherits, booleans false explicitly disable. Roots are selection only, not nullable.

3. Usage is computed per canonical concept across selected prose files in which that specific definition is effective (global/ancestor or explicit direct import). Only preferred and permitted aliases count; deprecated names do not prove correct use. Imports count as legitimate use of the original canonical definition; homonymous sibling definitions do not. Emit at most one unusedConcept per definition source/ref when enabled in at least one applicable selected file and no valid use is found across its effective selected files. Definitions, JSON catalogs, generated aggregate views are excluded from prose usage. Snapshot includes all catalog/policy bytes, Markdown/MDX membership, config and selected document content; SVG and CSS are excluded.

4. set-concepts publication/dryrun reads complete discovered catalog membership and raw bytes in the same snapshot, overlays the target after-image, checks target imports and prevents deletion/rename of definitions referenced by valid other catalogs. Target valid-before definitions cannot be removed while another malformed catalog makes reverse references unknowable. Malformed target can be explicitly repaired; known valid importers must resolve after repair. Existing unrelated malformed/dangling catalogs remain diagnostics and do not block additive repairs, but checks/index never report them as clean. No writing-policy parsing is needed to set a catalog.
Persist catalog dependency guard in the journal for set-concepts ONLY: sorted canonical path + raw-content digest for EVERY other discovered catalog, target excluded. Preflight verifies exact current membership and digests, including after restart; newly added/removed/edited importer means RecoveryConflict and no writes. Require this guard for set-concepts and reject the field on unrelated operations. Publication validates planned after against current dependencies and CAS; prepared recovery validates non-null strict after and unchanged dependency guard, then restores EXACT before bytes (even null/malformed), WITHOUT requiring before to parse. committed recovery checks same dependencies and target after-image, then retains committed bytes. A forged guard cannot omit known paths because exact discovered membership is checked. Direct imports target only recognized catalog paths and directly owned IDs. Do not add recursive import semantics. Other journal formats/operations remain untouched. Existing writing/v1 journals refuse current recovery before mutation; saved previous CLI performs one-off recovery first.

5. Migration is explicit author-reviewed replacement through current tools, not an automatic inferred converter: show v1 raw/digest -> concepts.set JSON definitions/aliases/deprecated with catalog CAS -> writing.set v2 with policy CAS. concepts.set examines catalog deps but not writing policies, so v1 cannot block migration. During the interval ordinary docs checks return WritingMigrationRequired; writing.index and individual show repair paths still work. Each invalid owner can be repaired independently subject to reference protection above. No Markdown table runtime interpreter in v2; preserve old prose and explain that only JSON now owns structured definitions. No fabricated definitions or automatic deprecated decisions.
Init may add docs/concepts.json ONLY if missing, before null, exact strict EMPTY catalog {format:'concord.concepts/v1',concepts:[]} without imports, with the genuine init transaction/new config binding already required. No local catalog or writing policy exception in init. Existing global catalog is preserved byte-for-byte, including invalid content. Recovery and normal publication enforce identical exception. Extra arbitrary JSON is never allowed. c-001 and old active writing descriptions updated to authoritative JSON/scoped path rules; historic adopted decision evidence is retained with explicit supersession link, not history rewritten.

6. Frontend state and responses bind (kind,path,request generation), not digest alone. Scope switch invokes dirty protection; stale A responses cannot update B. Policy and catalog have independent saved baselines; saving one never marks the other clean. A mutation returns its exact committed owner/digest; refresh only updates baseline if same path/kind/digest and generation, otherwise retains draft and shows external-change warning. Concept changes/inherited external change invalidate any claim of correspondence; check UI always describes a historical input snapshot and explicitly shows actual scope/mode. Add real browser tests for A->B delayed response, one save success/one conflict, and inherited-catalog external mutation.

### 同一概念的跨语言同名

同一 canonical 概念可以在 en 与 api 等语言列复用相同 preferred/允许名称；聚合与检查按概念身份去重。每列内部重复仍拒绝，允许与弃用语义集合不能跨语言相撞，同一弃用名也不能产生不一致的首选建议。
