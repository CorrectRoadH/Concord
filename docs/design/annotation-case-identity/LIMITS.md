# 约束

## L1: 只采用路径注释关联方式

只采用 `@feature` / `@use-case` 路径注释，不保留旧 ID、标题 token 或 testing owner 接入方式。来源：原设计约束。判定依据是候选是否排除这些旧入口。

## L2: 每个声明恰有一个契约目标

每个声明恰有一个契约目标，同一契约可有多个测试。来源：原设计约束。判定依据是候选的关联规则是否表达单目标、多测试关系。

## L3: 原生收集与正式执行归消费仓库

原生收集与正式执行仍归消费仓库负责。来源：原设计约束。判定依据是候选是否保持 Concord 的静态关系发现与消费者执行/证据边界分离。
