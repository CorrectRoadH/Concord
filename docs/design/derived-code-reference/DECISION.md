# 实现声明自动派生查询引用

## Decision

Selected: [derived](plans/derived/README.md)

## Rationale

2026-09-20 独立 Herdr Astra 挑战 `concord-code-id-grill-0920` 在三项问答后给出 PASS，采用自动派生方案。裁决通过 `concord design decide` 记录，当前契约仍由源码归属 Use Case 拥有。

派生引用的关键裁决：引用可能失效或被另一声明复用；冻结基于完整 AST 的静态名称与兄弟序号元组；无效 begin 仍占据边界栈。具体算法见[架构](plans/derived/architecture.md)。

G1: derived 保留无参数范围标记和显式 `@concord-implements`，维护者不需要另行命名；原文支持该目标。

G2: Concord 从源路径与结构位置派生当前查询引用，候选正文明确保留查询服务；原文支持该目标。

G3: 当前原文说明派生定位，但未提供对所有普通编辑场景的实际执行验证；该目标待验证。

G4: 完整 AST 静态名称与兄弟序号元组提供结构区分，缓存清空、进程重启和新 clone 的可重建性仍须实际验收；该目标待验证。

G5: 原文明确引用不承诺重构前后身份连续，且保留 Engineering、trace、review 和 Web 入口；原文支持该目标。

随后用户明确项目尚未发布，不承担旧命令与语法兼容：删除按声明 ID 查询的命令及迁移专用分支，直接维护无参数范围标记。此项为用户对范围的明确修正，不将原挑战 PASS 冒充为修正后实现的验收。

显式 ID 或自动写回 UUID 仍保留源码身份维护，私有身份表无法由源码重建，行号与函数体哈希会因普通编辑抖动，因此未采用。

设计 PASS 不代替实际验收。派生稳定性与复用、解析边界、打包 CLI、Web 无 ID 流程、Engineering 与证据隔离，以及完整 pnpm check 仍须实际验收。代码引用不能用于 CAS、授权或历史连续性证明。

## Rejected Options

显式 ID 继续使用手写 ID，或由工具生成 UUID 后写回范围标记。位置移动可以保留身份，但每段声明仍需要额外的身份字段与复制/冲突维护；不满足用户取消源码身份定义的目标，因此未采用。

## Residual Risks

引用可能失效或被另一声明复用；重命名、文件移动、匿名节点或同描述节点顺序变化不具有永久身份保证。实际派生稳定性、复用、解析边界、打包 CLI、Web、Engineering 与证据隔离仍需验收，设计 PASS 不能替代实现证据。
