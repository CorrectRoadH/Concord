# 文档目录与历史格式迁移裁决

## Decision

Selected: [preserve-identities](plans/preserve-identities/README.md)

## Rationale

选择 preserve-identities。目录用于组织，owner ID 继续标识独立文档。Research 统一以目录 README 为 owner，附页不带 owner metadata；顶层主题只从物理目录派生，不增加注册表。

离线工具保存原路径、实际字节摘要、Git 基线和逐项分类。当前关系及 Markdown 链接随路径重定向；历史、执行收据和来源路径保持原声明。原文明示的取消、暂缓、选择分别进入 cancellation、deferral、decision，不推断未知裁决时间。

G1: preserve-identities 的目标是完整发现，但原文要求实际从打包 CLI 和 Web 入口核对；设计记录保留该验收要求，当前文档迁移本身不冒充 Web 验收。

G2: 方案明确新研究只有标题，可自由添加安全相对路径 Markdown；原文支持自由正文、章节和附页。

G3: 方案保留 owner ID、原路径、实际字节摘要、Git 基线和逐项分类，并精确重定向当前引用；原文支持身份、来源、历史和引用保留。

G4: 方案应用完整前像、共享锁和 journal 一次发布，并要求输入漂移零写入、拒绝篡改计划和共享 journal 恢复；这些是验收条件，未将设计描述冒充实现结果。

G5: 方案保留取消、暂缓和实际选择，历史未明示的裁决时间不推断；原文支持可辨认状态。

保留单文件无法满足目录体验，也会使命令和界面出现两套创建模型。将整个主题合并为单一 owner 会删除既有身份，改变引用及嵌套归属。保留身份方案满足 GOALS 的 G1–G5，代价是迁移时必须核对全部路径与引用。

Herdr 独立只读 design_grill（GPT-6 Astra）已对所有权、历史日期、计划信任边界和当前/历史引用区分提出问题。逐项回答并明确验证契约后给出 PASS；交接保存于本轮外部审计记录。该裁决不替代实现验收。

## Rejected Options

保留单文件无法满足目录体验，也会使命令和界面出现两套创建模型，旧数据不能获得一致目录入口。

将整个主题合并为单一 owner 会删除既有 ID、关系与嵌套归属，违反身份保留约束。

## Residual Risks

必须验证完整清单、无新目录抢占、输入漂移零写入、拒绝篡改计划、重复应用和共享 journal 恢复。迁移前的执行证据不会因路径改变自动有效。实际源码链接与历史字符串需按类型区分，禁止全局文本替换。独立挑战已对所有权、历史日期、计划信任边界和当前/历史引用区分提出问题并在交接中保存 PASS；该裁决不替代实现验收。
