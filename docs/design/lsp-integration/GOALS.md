# LSP 集成

## G1: 非 TypeScript 代码可以声明实现

Python、Go、Rust 与 Java 的源码标记拥有实现关系；符号定位可补充函数、方法或类型范围。评价关系是否独立于缓存，以及各语言 profile 能否在支持的 server 版本上准确定位；符号不可用时仍显示标记行。

## G2: 非 TypeScript 测试得到相关性判定

显式分析可以观察测试调用的实现，输出共同契约中的 `observed` 或 `not-observed`。评价正向调用样本、声明层级与分析缺口，不要求证明测试与行为无关，不以未观察结果占比作为通过门槛。

## G3: 编辑器内可以看到 Concord 关系

提供诊断、定义、引用、补全与悬停。全部能力基于同一个 overlay 版本和磁盘来源集合；响应淘汰、未保存跨文件引用和不完整状态是验收条件。

## G4: 新语言不修改 Concord 即可接入

评价项目能否通过受校验的配置提供语言 profile 与外部 server。配置命令不等于支持任意语言；需要新的词法或绑定规则时仍需修改 Concord，并明确能力缺口。

## G5: 分析结果可重建

清空缓存不改变源码关系与代码关联身份。固定可复现输入、profile 与 server 环境时可比较定位与正向观察；不承诺任意 server 的内部索引、环境依赖或动态派发结果确定。
