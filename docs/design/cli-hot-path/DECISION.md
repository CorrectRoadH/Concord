# CLI 热路径与 HawDB 进程模型

## Decision

Undecided.

## Rationale

待独立复审与原生维护实测后裁决。当前比较：per-command-open 不满足 [L5](LIMITS.md#l5-按引擎规定持有-hawdb)。它让许多短命进程轮流打开一个按引擎规定只能由一个进程持有的目录，引擎后台维护无法运行，并发命令只能互相竞争并回源，因此 [G5](GOALS.md#g5-并发调用互不串行) 不满足。它也只能部分满足 [G1](GOALS.md#g1-启动在-50-ms-以内)：spike-startup 实测，完全打包后真实命令进入命令逻辑前仍约 139 ms。

hawdb-owner-service 以一个共享的后台进程满足引擎规定，并让 CLI 成为只转发参数的薄客户端。两者都保留现行的来源读取与摘要核验，不修订宪法。剩余待验证项是引擎维护的实际效果、版本交接、进程内回退，以及命令迁移到调用上下文服务后与独立进程输出的一致性。

## Rejected Options

待裁决。

## Residual Risks

- 启用 background-maintenance 后的原生产物体积、编译时间与维护所需的空闲时间尚未实测。
- 同步调用桥（worker 线程与 `Atomics.wait`）给每次存取增加的耗时尚未实测。
- 后台进程是新增的失败面：陈旧 socket、交接超时、测试中的进程残留与信号转发须由 C13–C16 覆盖。
- 第 3 阶段需要把约 130 处进程级状态用法迁移到调用上下文服务；遗漏任何一处都会让后台执行与独立执行的结果不同。
