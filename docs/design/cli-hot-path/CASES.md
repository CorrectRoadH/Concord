# CLI 热路径与 HawDB 进程模型

所有场景在参照消费者上执行；「同源重建」指同一来源状态下 `--fresh` 且缓存关闭的结果。

| Case ID | User Problem | Fixed Input | Acceptance Result |
|---|---|---|---|
| C1 | agent 连续多次检查未改动的仓库 | 缓存已热，来源不变，连续运行 `concord check` 20 次 | 每次结果与同源重建一致；p50 满足 G2；未变来源不调用解析器（以解析计数验证） |
| C2 | 编辑后立即检查 | 修改一篇文档的正文，大小不变，在同一秒内运行 `concord check` | 检测到变更，结果与同源重建一致 |
| C3 | 只改时间戳 | 对未改内容的文件执行 `touch` | 结果与同源重建一致；允许重读该文件 |
| C4 | 编辑器原子替换保存 | 写临时文件后 rename 覆盖原路径（新 inode），内容改变 | 检测到变更 |
| C5 | 工具保留 mtime 复制 | `cp -p` 或 `touch -r` 使新内容与旧文件 mtime、大小相同 | 检测到变更（ctime 推进） |
| C6 | 切换分支 | `git switch` 改动 300 个来源文件 | 结果与同源重建一致；增量只与这 300 个文件相关（G3） |
| C7 | 长期使用 | 对同一缓存执行 10000 次写入代次（含刷新、清理命名空间） | 物理体积与打开耗时满足 G4；已膨胀到 466 MB 的现有缓存在首次可写使用后回到 G4 范围 |
| C8 | 两个 agent 同时检查 | 同一 worktree 并发运行 4 个只读命令 | 各自结果与同源重建一致，耗时满足 G5 |
| C9 | 缓存损坏或被删除 | 删除或截断 `cache.hawdb` 中的文件后运行命令 | 回源得到与同源重建一致的结果，并报告缓存状态；随后的运行恢复热路径 |
| C10 | 读取中被修改 | 命令读取某文件期间另一进程修改它 | 遵守现有漂移语义：不返回把新旧内容混在一起的成功结果 |
| C11 | 查看版本与帮助 | 在 shell 循环中运行 `concord --version`、`concord --help` | 满足 G1 |
| C18 | 相同字节换路径 | 把一篇 Research README 的字节复制为同目录的支持页面，或移动一篇文档 | 身份、具名错误与 findings 与同源重建一致，不复用其它路径的投影 |
| C19 | 依赖输入变化 | 字节未变，但权限、配置、concepts、写作政策或解析器 Schema 改变 | 依赖这些输入的结果全部失效，与同源重建一致 |
| C12 | 升级或重建 Concord | 换用解析器身份不同的安装后运行命令 | 旧投影不被复用，结果与同源重建一致 |
| C13 | 两个版本同时使用 | 同一 worktree 上交替运行两个安装身份不同的 Concord | 每次结果与该版本的同源重建一致；任何时刻只有一个进程打开该 HawDB 目录 |
| C14 | 进程被杀 | 持有 HawDB 的进程在处理请求中被 `SIGKILL` | 当前请求明确失败或在只读命令上透明重试；下一次调用正常得到结果，缓存可用或按损坏回源 |
| C15 | 大量临时仓库 | 测试在 500 个临时 Git 仓库上各运行若干命令 | 结果正确；结束后不残留 Concord 进程、socket 或打开的 HawDB 目录 |
| C16 | 无法启动后台进程 | 环境禁止创建 socket 或 detached 子进程 | 命令仍得到与同源重建一致的结果 |
| C17 | 检索 Memory 与 Issue | 缓存已热，运行 `concord memory recall`、`concord issue recall` | 结果与现行排序规则的同源结果一致；检索由引擎的全文索引完成 |
| C20 | agent 写入时面板打开 | 面板与 Web 打开，另一进程连续改写 3 个 Spec 与实现文件后停止 | 两者在停止后 1 s 内显示同一代次的内容与关系；中间不出现新旧混合的代次（G8） |
| C21 | agent 与面板并发 | 面板打开时，同一 worktree 并发运行 4 个只读命令与 1 个写命令 | 零 `HawdbBusy`，结果与同源重建一致；面板在写入后 1 s 内更新 |
| C22 | 工作树被删除 | 服务运行中删除该 worktree 或其 Git-private 目录 | 服务在 5 s 内退出，不残留进程、socket 与记录 |
| C23 | 面板与旧服务版本不同 | 换用另一安装打开面板，旧安装的服务仍在运行且 Web 有连接 | 新面板显示的是新安装的结果；旧服务在进行中请求完成后退出，Web 连接收到明确的重连提示 |
| C24 | 服务启动竞争 | 两个面板与一个 `concord view` 同时首次启动 | 只有一个服务；三者连接同一服务，无失败 |
