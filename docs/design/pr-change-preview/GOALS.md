# 变更审阅目标

## G1: 正确识别 PR 的改动

审阅结果只包含 PR 相对于实际合并目标分支引入的变化，不把目标分支的后续提交或本地未提交文件混入结果。依据为 [PR 用例](../../feature/web-workbench/use-case/review-pull-request.md)，验收场景 C1、C2。

## G2: 直接阅读文件和文档

用户通过预览链接选择变更文件、读取差异及 Markdown 正文，刷新后保持选择。依据为同一 PR 用例，验收场景 C3、C4。

## G3: 消费者接入简洁

消费者使用已安装包与正式命令构建预览，复用自身的静态托管与发布文件核验。依据为本地可安装约束与 NiceEval 接入需求，验收场景 C5。
