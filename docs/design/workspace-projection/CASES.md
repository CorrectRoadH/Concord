# 工作区只读投影

| Case ID | User Problem | Fixed Input | Acceptance Result |
| --- | --- | --- | --- |
| C1 | 编辑时工作台消失 | 已有可读代次；扫描中一个已观察文件变化 | 工作台立即返回旧代次、构建时间和刷新失败；后续成功刷新替换它，绝不返回 409 作为导航结果。 |
| C2 | 首次启动遇到持续编辑 | 无缓存；源文件在全量扫描期间持续变化 | 前台返回明确的构建中状态并持续请求刷新；有界扫描可发布标明不完整及变化路径的导航代次，不能把未知关系显示为无问题。 |
| C3 | CLI 需要当前事实与展示视图 | 相同 worktree、配置和安装身份；Web 已有一代缓存 | workspace show 仍扫描当前来源；显式缓存入口读取相同代次及历史状态，缓存不可用具名失败。 |
| C4 | 编辑器看到旧代次 | 定向读取 B 后产生草稿，较旧工作区代次 A 乱序到达；外部又写入 C | A 不替换 B 或草稿，最多触发定向核对；提交仍使用 B 的 digest，遇 C 返回冲突并保留草稿。 |
| C5 | 刷新资源有界 | 并发浏览器请求、服务重启、缓存损坏或原生模块不可用 | 同身份单刷新 owner、规定超时与容量；重启可读完整代次；损坏或原生不可用具名不可用且不回源扫描。 |
| C6 | 配置更改改变投影身份 | 编辑 concord.config.ts 后旧键仍有完整代次 | 新配置只读新键，先显示构建中；旧配置的代次不跨身份展示，当前配置编辑的前像来自定向读取。 |
| C7 | 自动保存与首次构建重叠 | 无缓存；工作台每 5 秒自动保存，发布后无待恢复 journal | 一次 60 秒扫描预算内提供 consistent:false 的安全导航，publication revision 漂移不使首次构建永久等待。 |
| C8 | agent 查询挤占缓存 | 已有工作区代次；trace/review 写满并淘汰 query_cache | 工作区代次仍可读，两个命名空间的配额独立。 |
| C9 | 中断发布阻断刷新 | 首次无缓存或已有代次时检测到 RecoveryRequired | 显示具名阻断及恢复按钮；恢复成功立即刷新。 |
| C10 | 新诊断不能被旧健康掩盖 | 已有一致且无 finding 的代次；下一次一致扫描新增 finding | 新 consistent:true、complete:false 代次替换旧代次并显示真实诊断。 |
