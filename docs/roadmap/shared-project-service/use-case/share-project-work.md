# Agent 与人共享查询和收集观察

## 从同一项目开始

Agent 在项目子目录工作，人从 Herdr 选择这个项目，或在另一个终端运行 `concord view`。项目中已经有测试标记与收集配置。

下列输出是预期结果；命令参数和票据结构由 [CLI 接口](../cli.md)拥有。

1. Agent 运行 `concord check`。Concord 定位项目目录并启动或复用[工作区服务](../../../concepts.md#workspace-server)，返回当前来源检查结果。
2. 人打开工作台。它连接同一实例，显示工作区服务维护的文档与关系。查看文件时定向读取当前正文，不用导航缓存当编辑前像。
3. Agent 直接修改 Spec。工作区服务发现变化并刷新，人看到变更；没有未保存草稿时可加载新正文，有草稿时保留草稿并显示冲突。
4. Agent 运行 `concord test discover`。CLI 等待结果，面板与 Web 显示同一个操作及进度。
5. 人关闭再打开面板。收集继续进行，重新打开后仍看到同一个操作；清单、label 与绑定按收集 Spec 产生，不表示测试通过。

## 结果与边界

同一项目目录任一时刻只有一个工作区服务和一个外部观察任务槽位。人和 agent 无需协调谁先打开界面；另一个客户端发起另一外部观察时得到忙碌结果，不重复启动相同收集或分析进程。

同一目录切换分支后，工作区服务复核配置与来源。另一个 worktree 属于另一个项目目录，拥有独立工作区服务、缓存与任务。

各客户端共享工作区服务的运行状态，但不会覆盖彼此的草稿、滚动位置或选择。共享历史投影不能使未经当前来源核验的检查成功（[只声称证明过的](../../../taste.md#t-5)）。
