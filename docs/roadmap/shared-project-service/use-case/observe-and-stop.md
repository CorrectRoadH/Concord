# 断线后确认操作与在 CI 中退出

## 确认断线的操作

CLI 或界面已经取得操作票据，提交写入或测试后连接断开。以下为预期行为。

1. 客户端重新连接同一项目目录，使用原票据查询操作。
2. 后台仍是同一实例时，返回执行状态或已保存的结果；客户端不重新创建票据执行相同写入。
3. 后台重启或记录已经淘汰时，客户端显示结果未知。使用者检查目标文件、测试证据、journal 或远端状态，明确决定下一次动作。
4. 有未完成 journal 时，运行 `concord recover`，按现行恢复协议处理。恢复材料不被缓存清理删除，也不由“文件看起来正确”替代。

准备输入时断线且尚未提交，不产生领域操作；过期准备会释放。票据的有效期与错误由 [CLI 接口](../cli.md)定义。

## 主动取消或停止

测试仍在运行时，使用者通过操作票据请求取消。界面先显示取消中，确认整个进程组退出后才显示已取消；清理失败时保留阻断及诊断。

写入已经进入提交区时，取消可能得到成功结果。取消不表示回滚；客户端必须读取终态。关闭浏览器只是断开连接。

`concord server stop` 停止接收新操作并收拢已有工作。另一个安装版本的 CLI 停止后台，再启动自己的后台。

## 在 CI 中使用

CI 在独立项目目录执行以下命令，结果为预期行为：

```sh
concord --server=command check
```

命令启动自己的受管后台，执行相同应用检查，取得结果并确认后台清理后退出。若该目录已有服务，则报告忙碌，不停止别人的实例。

同根 runner 内的 Concord 查询连接所属后台。修复核验的临时 worktree 由操作创建各自的受管后台，查询对应候选；先回收后台，再删除目录。CI 中断时也执行清理，无法确认就失败并保留恢复材料。
