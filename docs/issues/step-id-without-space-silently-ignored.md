# 中文步骤末尾的 `{#id}` 缺少前导空格时被静默当作正文

## 现象

2026-11-08 在 NiceEval 仓库整理 Use Case 时，发现 45 个步骤写成 `1. 列出项目中的 Run。{#list}`：`{#id}` 紧贴中文句号，没有前导空格。

- 其中 15 处是仓库原有的，30 处是 coding agent 新写的。
- 这些列表项都不是步骤，页面把 `{#list}` 显示成字面量，测试与代码也无法指向它们。
- `concord check` 对这些页面报告 `findings: none`。

## 原因

`src/model/markdown-facts.ts` 用 `/([ \t]+)\{#([^{}\s]+)\}$/u` 识别步骤 ID，要求至少一个空格或制表符。[步骤语法](../feature/local-sdlc/format.md#步骤语法)写明“第一段末尾带至少一个空格及 `{#id}`”，并规定“工具不发现误标”。

中文句末通常不写空格，所以作者与 agent 会反复写出这种形式。规则本身明确，但缺少反馈，错误只能靠人读源码发现。

## 期望

`check` 对有序列表项第一段末尾、紧贴非空白字符的 `{#id}` 给出具名 finding，提示补一个空格。这样不改变“合法位置上的该语法都按步骤解析”的规则，只为常见漏写提供反馈。

## 后续

- 判断该提示属于 `check` finding 还是 advisory，并写进[步骤语法](../feature/local-sdlc/format.md#步骤语法)。
- `use-case format` 是否顺带补空格，需要与“只做声明的格式化”的现有边界一起裁定。
