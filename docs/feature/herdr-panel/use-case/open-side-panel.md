# 在 Herdr 中打开 Spec 面板

维护者在 Herdr 中按下 Concord 插件的快捷键，或在任意终端运行 `concord panel`，打开当前工作树的 Spec 面板。

## 主流程

1. 在 Herdr 中触发插件，面板在当前 pane 右侧打开，读取该 pane 所在的工作树；在其它终端中运行 `concord panel`，读取当前目录所在的工作树，或用 `--root` 指定。
2. 面板左栏列出分类：Feature、Engineering、Design、Roadmap、Research 与文档；选中分类后列出其中的条目，Feature 下展开它的 Use Case。
3. 选中条目，右栏显示正文；用方向键或 `j`/`k` 移动，回车进入，`Esc` 返回，`/` 筛选当前列表，`Tab` 在栏之间切换，`q` 退出。
4. 仓库文件变化后，面板显示新内容，保持当前的选中项与滚动位置。

## 验收

- 工作区已有可读投影时，从启动到首屏可读不超过 300ms，不触发全量扫描；尚无投影时显示构建中，完成后自动替换，不出现空白屏。
- 文件写入停止后一秒内显示新内容；选中项被删除时选中其所属条目，没有所属条目时选中列表首项。
- 宽度不少于 60 列时双栏显示，更窄时单栏，栏之间用 `Tab` 切换；终端尺寸变化后重排，保留选中项。遵守 `NO_COLOR`，不只靠颜色区分状态。
- 当前目录不在 Git 工作树中，或工作树没有 Concord 配置时，显示原因与 `concord init` 提示并以非零码退出。配置无法读取时显示配置诊断，不显示为待初始化。
- 一个 owner 无法解析时，在它的位置显示诊断，其它条目照常显示。
- 面板运行期间，同一工作树上的 CLI 调用不因面板而失败、等待锁或报告 `HawdbBusy`；多个面板可以同时打开。
- 面板不写入任何仓库文件。面板进程退出后，它自己的连接、输入监听、定时器与渲染资源全部释放；面板启动的工作区服务按服务规则在空闲后退出。
- Herdr 插件随 Concord 包发布，位于包根的 `herdr/`。维护者以 Herdr 安装该目录，并以环境变量 `CONCORD_INSTALLATION` 指向这份 Concord 的包根；插件的构建步骤把这份 Concord 的入口与 Node 的绝对路径写入 Herdr 的插件副本，之后不依赖 PATH。未安装 Herdr 时 `concord panel` 照常运行。
