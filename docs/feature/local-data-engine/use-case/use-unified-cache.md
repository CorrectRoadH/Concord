# 使用统一的可重建持久缓存

缓存的 `ready` 状态表示投影可读取，不表示某次扫描命中。扫描分别报告测试与代码缓存的状态、命中数和未命中数；不可用时保留原因，回源结果仍需通过来源一致性核验。

集合读取采用有界批处理，避免每个文件单独维护整个缓存。一个文件解析失败不丢失其他文件的结果；缓存损坏、不可用及批次超出预算时仍遵守回源行为。批处理不改变持久格式、资源所有权或清理协议。

批量写入同时遵守条数和 UTF-8 字节预算。没有任何测试标记候选的文本不构建 JS/TS 语法树；存在候选时仍通过注释范围校验，不能把字符串、模板或正则中的伪标记计为声明。

缓存目录的总容量与文件数量不限制打开、状态检查和清理。清理完整检查目录及链接，在原生 Ownership guard 内删除缓存数据并保留锁 inode；异常路径不因目录较大而跳过校验。单次输入和内存命名空间的资源边界与目录检查分别定义。

缓存目录的物理体积有上限：按 inode 去重后不超过持久逻辑总预算的 2 倍加 32 MiB。可写使用结束时体积超过 48 MiB 的命令，在返回前启动一个 detached 的缓存维护进程，本命令不等待。维护进程不持有命令的句柄：先以可写方式打开缓存，checkpoint 后回收不可达的引擎对象并关闭；回收后仍超过上限时，按清理协议取得协调与 Ownership guard，重新完整检查后丢弃缓存数据。取不到句柄或协调时直接退出，由下一次触发的命令再次启动。工作区服务运行时，由服务在空闲时执行同样的回收与丢弃，不另启维护进程。回收与丢弃都不改变任何命令结果，丢弃之后的命令冷启动重建。`cache status` 报告物理体积与上限。

启用缓存的工作区扫描可以恢复固定引擎版本明确报告的只读行增量恢复失败：以 existing-only 可写句柄恢复日志并 checkpoint，再重新只读打开。恢复不得删除目录、覆盖文档或创建缺失数据库；缓存关闭模式和普通只读调用不启用该恢复。恢复失败仍报告不可用。

用户在隔离 Git 消费者中安装打包后的 Concord，执行 scan、code scan、反馈列表及 cache status/rebuild/clear。注解、代码、配置和远端快照使用同一 HawDB 目录，彼此以命名空间隔离。

连续命令可以命中缓存；编辑、新增或删除来源立即使对应键失效。数据库缺失、损坏或 payload 不合 Schema 时，源码解析回源并报告缓存状态。数据库被其他进程占用时，源码解析改用本进程的内存缓存照常完成，缓存状态报告 `HawdbBusy` 原因；远端快照与诊断投影在工作区服务运行时经由服务读取，没有服务而库被占用时报告不可用，不当作空集合。远端快照失败不触发网络请求，不覆盖已捕获的本地 Issue。一次完整远端 fetch 的合并具备事务原子性、单调时间戳及同版本冲突保护。

clear 只删除 Git-private 的 cache.hawdb 内的缓存内容，拒绝 symlink、越界、外部硬链接和活动句柄。完整计数的内部硬链接允许清理。目录、根 owner.hawdb.lock 及同级 cache.hawdb.concord.lock 的 inode 保留；重建后来源内容和证据摘要不变。

普通只读查询不修改来源；工作区服务可以保存查询产生的可重建缓存行，读取也允许已有缓存内部派生文件重建及协调锁创建。读取可能需要可写缓存目录。dry-run 与 cache-off 不访问持久数据库；feedback 继续使用本地 Issue 已捕获的来源信息，不触发远端请求。

dry-run cache status 只检查路径和原生产物。缓存缺失或 owner-only 时返回 empty；其它情况返回 unavailable，detail 说明持久访问关闭，不以未执行的读取声称 ready。普通 cache status 仍核验实际投影。

缓存只对写入它的 Concord 引擎版本有效。换用引擎版本不同的 Concord 时，缓存按不可用处理并重建；远端观察需要显式刷新，本地已捕获 Issue 保留。

clear 的 dry-run 展示引擎、缓存路径、存在性、待删除的顶层条目、保留路径和原生产物可用性。预览不取得原生清理锁、不创建缓存；实际执行重新检查路径和所有权，预览成功不授权删除。工作区服务运行期间长期持有持久缓存，CLI 本地操作通过只读快照与派生批次使用缓存，远端快照与诊断投影经由服务读取；clear 经由服务执行。`cache status` 报告服务的 pid、安装身份与当前结果的 `sourceDigest`，没有服务时报告由当前进程持有。

缓存状态检查验证安装包的原生产物，缓存目录缺失不掩盖安装故障。扫描和状态查询对同一原生产物摘要错误提供一致的诊断，包含产物路径、预期与实际摘要，以及修复安装的提示。清理缓存不能修复安装产物。

进程对原生产物加载失败保留一个有界失败记录，一秒内复用该失败，随后重新验证安装产物。期间缓存调用继续按不可用回源，不能返回未经验证的缓存成功；安装修复后长期进程可在下一次重试恢复。该退避只限制重复安装检查，不跳过来源摘要、Schema 或扫描一致性验证。

缓存目录不存在时 clear 无操作；只有完整预检为 owner-only 的目录报告 empty，未知内容不归为空。清理中断或部分失败保留现场并具名报告，再次 clear 继续完成。清空后远端观察只能由显式刷新重新获得。

## 验收

- 缓存冷热命中、损坏、陈旧 payload、源码变化后的旧键、解析结果为 undefined、短期缓存达到容量、同进程多个命名空间，以及 CLI 与 Web 交替读取。
- 重复进程、事务回滚、提交前 SIGKILL 后重开、已提交 WAL 恢复，以及没有工作区服务时快照结束后的句柄释放；远端旧版本与同版本冲突。
- 真实旧缓存的升级接入、逻辑只读，以及已有完整缓存上的 dry-run 与 cache-off；验收使用独立新进程，避免进程内配置命中掩盖持久访问。
- 工作区服务运行时，4 个只读命令与 1 个写命令并发，全部成功且不以 `HawdbBusy` 失败；服务运行时 `feedback list` 的远端快照与只运行 CLI 时相同；三个启动者同时启动只得到一个服务；服务在请求中被 `SIGKILL` 后下一次调用正常；临时仓库使用 `--server=command` 查询时，命令结束前回收后台进程。
- 同进程双向与跨进程的句柄互斥，clear 与直接调用 HawDB 的分支句柄双向阻止并报告 busy 类别；损坏库的受锁清理、空库重开、根锁与同级锁 inode 保留。
- 缓存目录外的其它文件、目录或内部文件为 symlink、跨目录内部链接与外部链接、内部锁别名、预检后链接或身份变化、新增成员，以及中断清理后的重试。
- 清空后离线读取本地 Issue；无 SQLite 运行时导入。
- 在没有 Rust 的隔离消费者中离线安装打包 CLI 后实际操作，覆盖 Linux 与 macOS 原生产物及产物缺失或身份不匹配。
