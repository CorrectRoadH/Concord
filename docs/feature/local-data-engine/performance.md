# 本地数据引擎的性能测量

本页拥有 local-data-engine 的测量场景与预算，方法见[性能测量](../../engineering/performance/README.md#测量方法)。场景直接使用 Mitata，入口为 `bench/local-data-engine.bench.ts`。

## 测量场景

| 场景 | 测量内容 |
| --- | --- |
| `local-data-engine/source-scan` | 当前来源关系扫描 |
| `local-data-engine/cache-status` | 读取真实缓存状态 |

计时边界为进程内真实操作与其自身资源释放，排除 CLI 宿主启动和格式化。固定输入、消费者与缓存状态由场景源码声明；修改这些条件时重新建立参照结果，不使用整进程数字作为操作预算。

Mitata 的成功退出表示测量完成，预算由交付者对照适用条件与原生统计判断。没有相同边界的参照证据时只报告测量结果，不宣称预算通过。

## 刷新上限

后台关系缺口、Feature 关系与审阅材料刷新，从等待同键刷新到扫描子进程退出的总时间不得超过 120000ms。超出即终止扫描、不发布结果，没有上一代投影时返回 QueryPending。该约束需要真实刷新生命周期证据，不能由 Mitata 的批次统计或 `stats.max` 证明。

## Memory 与 Issue 检索 {#knowledge-search}

检索优化的测量沿用 `bench/local-sdlc.bench.ts` 中的真实应用查询入口，场景由[本地 SDLC 性能页](../local-sdlc/performance.md)拥有。实现检索架构时在同一入口覆盖以下固定条件；文档约定不代表场景已经执行或通过。

| 条件 | 输入与观察 |
| --- | --- |
| 首次构建 | 独立仓库、空搜索缓存；分别记录完整来源核验、索引构建及第一次查询的时间 |
| 稳定热查询 | 100、1000、10000 篇固定文档，每篇约 1 KiB，中英文混合；Memory 和 Issue 分别测量；不同查询词，避免结果缓存掩盖执行 |
| 单文件增量 | 从相同的热状态只改一篇正文；计入变化发现、重读、索引提交和查询，不只测数据库谓词 |
| 重启和 clear | 相同文件集合重新打开或清空，计入重新核验或重建；不能与活跃进程的热查询混作一组 |
| 高频命中 | 单字、常见词和全部命中，报告完整结果的构造与传输成本，不用 top-k 隐藏成本 |

每个规模固定零命中、少量命中和高命中率的词项。计时覆盖请求前的来源核对、HawDB 执行、完整结果读取与资源释放，排除 CLI 启动、Fixture 准备与人读格式化。对照扫描使用相同正文、匹配规则、来源一致性和结果集合；两边结果须先通过等价性验证。

性能验收同时检查工作量：稳定热查询的来源正文读取与重解析为零；单文件变化只读取和解析必要的变化正文；跨原生边界只返回命中记录与有界元数据。目录与文件身份检查单独报告，允许随文件数线性增长，不把它算成零 I/O。

10000 篇、少量命中的基线必须观察到实际属性索引读取，不能只凭 `EXPLAIN` 的计划名称判断。记录候选访问、属性页读取、索引工作内存及返回字节数；原生执行内部退回全正文扫描、建立整库正文副本或传回全量正文后宿主过滤，都不满足索引加速验收。小集合或高命中率下的优化器扫描单独报告。

引擎条件分别覆盖带 work budget 的持久查询、checkpoint 前后的 live delta，以及内存降级。固定引擎的 `bounded_work`、缺 canonical base 或缺持久属性投影路径会直接扫描，已有持久索引也仍需访问 live delta；不得去掉资源预算来制造索引命中。正常持久路径须在保持预算的条件下满足上述验收；内存降级按等价性和完整成本报告，不因存在同名 `FULLTEXT` 描述符就宣称同等加速。

耗时使用 Mitata 原生统计，并与同机、同输入的完整来源扫描比较。尚无符合此边界的基准证据，不声明毫秒阈值或倍数承诺；实现交付须给出三个规模的对照结果及瓶颈，成功采样不能代替上述工作量验收。
