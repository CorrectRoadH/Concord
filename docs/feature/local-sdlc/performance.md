# 本地 SDLC的性能测量

本页拥有 local-sdlc 的测量场景与预算，方法见[性能测量](../../engineering/performance/README.md#测量方法)。场景直接使用 Mitata，入口为 `bench/local-sdlc.bench.ts`。

## 测量场景

| 场景 | 测量内容 |
| --- | --- |
| `local-sdlc/documents-list` | 读取文档列表 |
| `local-sdlc/search/{kind}/{storage}/{size}/{state}/{hits}` | 核对当前来源并检索完整 Memory 或 Issue |
| `local-sdlc/search/{kind}/scan/{size}/{hits}` | 相同来源、匹配与结果边界的完整 JavaScript 扫描 |
| `local-sdlc/trace-check` | 核验当前关系 |
| `local-sdlc/check` | 合并当前来源检查 |
| `local-sdlc/code-list` | 读取代码声明 |
| `local-sdlc/test-list` | 读取测试声明 |

计时边界为进程内真实操作与其自身资源释放，排除 CLI 宿主启动和格式化。固定输入、消费者与缓存状态由场景源码声明；修改这些条件时重新建立参照结果，不使用整进程数字作为操作预算。

Mitata 的成功退出表示测量完成，预算由交付者对照适用条件与原生统计判断。没有相同边界的参照证据时只报告测量结果，不宣称预算通过。

## Memory 与 Issue 检索 {#knowledge-search}

检索矩阵的测量要求见[数据引擎的检索测量](../local-data-engine/performance.md#knowledge-search)。场景使用真实应用入口、`LocalRepository` 来源快照和官方 HawDB 数据库 Worker。

`kind` 为 `memory` 或 `issue`，`storage` 为 `persistent` 或 `memory`，`size` 为 100、1000、10000 篇。每个种类与规模共享一组确定性来源，每篇 UTF-8 文件为 1024 字节，正文混合中英文。场景不共享数据库句柄或代次。

`memory` 的 Worker 打开真实内存库，不打开持久库。应用请求预先选择内存模式，由活跃 owner 持有真实内存库。Fixture 不注入持久库故障，不通过失败改变存储选择。

内存模式首次查询和重开包含内存构建，正文读取计数覆盖完整来源核验。稳定热查询要求零正文读取，单篇变化要求一次。它与每次创建临时 Worker 的独立命令不同；故障通知及服务生命周期由功能测试验收。

| 状态与词项 | 输入和计时边界 |
| --- | --- |
| `cold/{zero,rare,high}` | 空搜索投影；计入全量正文读取、解码、首次构建及查询。Worker 和空库的打开在计时外 |
| `warm/{zero,rare,high}` | 已核验完整集合；每次轮换三个词项，分别命中 0、2、全部文档。高命中轮换单字、英文常见词和全部命中的词 |
| `change/rare` | 计时外预热后原子替换一篇正文；计入变化发现、一次重读、增量提交与完整查询 |
| `reopen/rare` | 1000 篇代表输入；计入真实 Worker 排空、数据库与来源适配器重开、全量来源核验及查询。内存库重开重建投影 |
| `clear/rare` | 1000 篇持久库代表输入；计入真实 Worker clear、owner 失效、来源核验、重建及查询 |
| `warm/no-gram` | 1000 篇代表输入；轮换 U+0085 及其与常见词的 AND 组合，命中一篇，包含完整零命中正则复核路径 |
| `scan/{zero,rare,high}` | 同规模、同种类的完整来源读取和严格解码、JavaScript 子串匹配、排序及完整结果构造 |

查询计时保留来源身份发现、返回前元数据核验、原生谓词、完整结果传输和操作自身资源释放。Fixture 创建、等价性检查、来源编辑、缓存预热与场景最终关闭在计时外。系统文件缓存不清除；冷仅指搜索投影为空。

Mitata 的计算参数为每次冷查询及增量、生命周期场景准备独立数据库会话，不自行扣减时钟。完成的会话在下一次准备或场景关闭时排空；异常时由外层 Scope 释放。

每个种类、规模和存储组合在计时外先核对各词项的完整结果与 JavaScript 扫描等价，包括路径、正文、摘要、顺序和 Issue provider。观察适配器委托真实来源读取，断言热查询正文读取为零、单篇变化读取为一，失败使测量失败。

准备阶段输出来源正文读取数、身份发现次数和文件数，以及跨 Worker 返回的行数、文档与代次 JSON 字节数。字节数在计时外计算，不代表 FFI 或结构化克隆的物理字节数；采样期间不保留观测用的原生结果副本。

原生候选访问、属性页读取、索引内存与内部批次耗时不可观测；来源适配器计数也不包含内部 stat 系统调用数。不以查询计划、成功采样或零正文读取推断索引加速。正常零命中包含额外正则扫描，与有命中场景分别报告。

耗时使用 Mitata 原生报告，在同机同输入下与 `scan` 对照。没有可比测量时不声明加速倍数或毫秒预算；成功采样也不能代替工作量断言。
