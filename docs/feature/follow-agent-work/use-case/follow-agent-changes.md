# 跟随 agent 的改动

agent 在工作树中写入文件时，维护者在侧边面板或 Web 工作台的「跟随」入口中实时看到它触及了哪些 Spec。

## 主流程

1. agent 修改文档、实现或测试文件。
2. 面板在写入停止后一秒内更新关注范围：新触及的 Feature 与 Use Case 出现并标记为新增，不再被触及的移出。
3. 维护者的选中项与滚动位置保持不变；选中项移出关注范围时，选中它所属的 Feature，Feature 也移出时选中列表首项。
4. agent 提交后，已提交的改动不再属于关注范围；维护者按 `a` 查看全部。
5. 维护者切换到另一个工作树，跟随在其它 worktree 中工作的 agent。

## 验收

- 关注范围相对 HEAD 计算，包含已暂存、未暂存与未跟踪文件，遵守 `.gitignore`。改动的 Spec 文件直接计入；改动的实现与测试源码经源码标记与代码关联计入其指向的 Spec；新增的测试声明计入其指向的 Use Case。删除与重命名按改动前后的路径都计入。
- 每个被触及的条目显示触及原因：Spec 正文改动、实现改动或测试改动，以及对应的文件。
- 连续写入合并为一次更新，更新期间不闪烁，不清空列表。HEAD、index 与 `concord.config.ts` 的变化同样触发更新。
- 显示内容来自同一来源状态，不把新旧内容混在一起。一个 owner 无法解析时，在原位置显示诊断，其它条目照常显示。
- Web 工作台的「跟随」入口显示相同的关注范围与触及原因，同样在一秒内更新，不需要手动刷新；Web 中保存的编辑也在面板中一秒内出现。
- 切换工作树时，列表、状态与诊断都来自新工作树，不残留前一个工作树的条目。
