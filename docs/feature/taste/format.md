# 品味文件的格式

品味文件是 `docs/taste.md`，可以直接编辑。文件只保存当前正文，修改历史由 Git 保存。

## 结构

```markdown
# Concord 的品味

## 总则 {#general}

1. 品味是判断标准，不是逐条检查的规则。 {#general-use}

## T-1 读得懂胜过写得全 {#t-1}

Spec 没人看得懂，就没人认真审阅，也就没人维护。

- 好的样子：……
- 坏的样子：……
```

- 品味的标题形如 `## T-1 标题 {#t-1}`，标签与 ID 的数字一致。正文写它解决的问题和好坏对照，不分款。
- 总则写 `## 总则 {#general}`，其款写 `{#general-<name>}`。
- 每个条目都有 ID，全文唯一；ID 一经使用不改名、不复用，新条目取未使用的编号。
- frontmatter、代码、HTML 与注释中的 `{#...}` 不产生 ID。没有显式 ID 的标题不能作为链接目标。

文件没有 frontmatter，也没有草稿与生效两种状态：文件存在，其中的条目就生效。

## 链接

`docs/` 下除 `docs/_template/` 与品味文件本身外的 Markdown 正文都可以链接条目，只计入行内链接。链接相对所在文件解析，结果为 `docs/taste.md` 才是品味链接；不读取网络，不跟随 symlink。不带 fragment 的链接不建立关系。

Design 页与其它页面一样只写现在，其中指向不存在的条目的链接同样报告 `AnchorNotFound`。
