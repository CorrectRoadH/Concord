# 修改一页文档并检查

## 用户目标

维护者读 Spec 时发现一处要改，想当场改完并知道有没有弄断链接或用错词。

## 起始状态

- mod 正在显示 Feature `cart` 的 README。

## 完整路径

1. 点击要修改的段落、标题、表格或 Mermaid 图。只有这一块在原位置显示 Markdown 源码，其余正文保持排版；直接输入修改，不切换整页模式。 {#edit}

2. 停止输入 800ms，mod 自动保存；离开当前块时立即保存并恢复预览。页面没有编辑、保存、取消与格式工具栏。 {#save}

   mod 写回文件并读回确认后立即完成保存，然后独立在后台运行 `concord check`。换页、切换仓库和下一次保存不等待检查；连续保存合并为最新一轮检查。路径旁先显示“正在保存…”，写入完成后显示“已保存，正在检查…”；检查失败显示“已保存，检查失败”，不显示上一轮的检查结论。有问题时在正文上方显示结果。保存只写工作区文件，不暂存或提交。检查通过的状态为：

   ```text
   check: ok
   ```

3. 检查报告 finding 时，正文上方显示全仓库问题摘要，正文继续可读。 {#fix}

   ```text
   仓库有 1 个检查问题
   [查看详情]  [复制给 agent]
   ```

   点“查看详情”展开限高、独立滚动的列表，每项显示说明和文件位置；点一项打开对应源码，再点“收起详情”恢复紧凑摘要。即使仓库有 85 条问题也不会挤走正文。完整样式见[页面视图](../ui.md#页面视图)。

   点“复制给 agent”得到带机器、仓库目录和全部问题的修复请求，不必逐条复制。修好后后台刷新自动更新数量；全部解决后摘要消失。

## 结果

文件已保存，检查结果就在眼前。

| 情形 | 结果 |
| --- | --- |
| 点击 Mermaid、图片或 p5 图块 | 在该块原位置编辑 Markdown；离开后重新呈现。Mermaid 无效时显示错误与可点击的源码，不阻断保存 |
| 尚未修改，只打开或点击一块 | 不保存、不归一化 Markdown；块外的字节保持原样 |
| 保存前文件已被 agent 改过，尚未收到后台更新 | 用最新磁盘摘要提交本次编辑；保存竞争时重新读取再提交，不提供冲突与合并界面 |
| 收到当前文件的后台更新 | 直接载入磁盘内容，结束块编辑并取消尚未发出的保存；未保存输入被新内容替换 |
| 本次自动保存引起的后台通知 | 确认已保存内容，不打断光标、中文输入或更晚的输入 |
| 保存期间继续输入 | 同一文件串行保存，当前请求完成后保存最新输入；旧请求不能清掉新输入 |
| 切换文件或仓库 | 先提交已有输入到原文件，再切换；没有保存确认或放弃按钮 |
| 保存失败 | 显示错误，保留当前输入；继续输入或再次离开块时重试，后台文件更新仍直接载入 |
| 关闭面板 | 取消延迟任务并尝试提交尚未保存的输入；应用强制退出不保证完成写入 |
| 仓库在远程机器上 | 与本机相同，见[在远程机器的终端旁使用](use-on-remote-machine.md#edit) |
