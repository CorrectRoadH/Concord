# Concord mod 的界面

mod 的外观与 Herdr 自带的 Files、Changes 一致，看起来是 Herdr 的一部分，而不是一张网页。

## 外观

- 整个面板是一张卡片：`background` 底色、1px `border` 边框、10px 圆角。颜色一律取主题的颜色名，不写死色值，换主题时跟着变。正文 13px，路径与说明 12px，小标题与计数 11px。
- 顶栏高 42px，下面一条 `border` 分隔线。左边是粗体的“Concord”，接着是 `dim` 色、放不下时截断的仓库地址：本机显示以 `~` 缩写的路径，远程显示 `<机器>:<路径>`。右边不放按钮：mod 用来读 Spec，新建文档在和 agent 的对话里完成。
- 能点的东西看起来就能点：行高 28px、7px 圆角，悬停时 `hover` 底色并显示手形指针，当前打开的页面用 `selected` 底色。不能点的小标题（例如“守护它的测试”、步骤名）是 11px、`dim` 色，没有悬停效果，和可点的行一眼可分。
- 按钮高 28px，宽度随文字。主按钮用 `solid` / `solid_foreground`，一屏最多一个；其它按钮是带 `border` 边框的次按钮。正在执行的按钮显示进行中的文字（例如“正在保存…”），执行期间不能再点。
- 图标是随 mod 分发的 Lucide 线条图标（ISC 许可，写入 `NOTICE.txt`），按文字颜色着色：关闭与打开的文件夹、文档、Use Case、测试、代码、收起与关闭。
- 文件位置（`路径:行`）与代码用 Herdr 设置里的等宽字体。

## 双栏

面板始终是两栏：左边是文档列表，右边是页面，中间一条 `border` 分隔线。布局侧栏常常只有四五百像素宽，所以文档列表的宽度是面板宽度的 40%，介于 160px 与 240px 之间；页面占其余宽度。

顶栏最左边是收起按钮：点一下隐藏文档列表，页面占满面板，再点一下恢复。收起状态在刷新、换页与换仓库时保持。还没有打开页面时，右栏用 `dim` 色显示“选一页开始阅读”。

下面的线稿是约 480px 宽的侧栏。分组标题和带图标的行可以点；正文点击后在原位置编辑，路径与小标题不能点。

```text
┌──────────────────────────────────────────────────────────────┐
│ ◧  Concord  ~/code/shop                                      │ 顶栏 42px
├───────────────────┬──────────────────────────────────────────┤
│ FEATURE  3        │ docs/feature/cart/README.md              │ 路径行
│ ▣ 购物车          │┃ 1 个问题                                │ 检查横幅
│   ◇ 加入商品      │┃ cart/README.md:12  单子→订单            │ ← 可点
│   ◻ 架构          │                                          │
│ ▣ 结算            │  # 购物车                                │ 正文
│ ENGINEERING  2    │  把商品放进购物车，数量自动合并……        │
│ ▣ 构建            │                                          │
│ 项目规则  3       │ ──────────────────────────────────────── │
│ ISSUE  1          │ 守护它的测试                             │ 小标题，不可点
│                   │  open-feature                            │ 步骤名，不可点
│                   │   ⚗ adding the same sku…  cart.test.js:1 │ ← 可点
│                   │ 实现它的代码                             │
│                   │   ⟨⟩ addItem            src/cart.js:8    │ ← 可点
└───────────────────┴──────────────────────────────────────────┘
```

| 元素 | 能点吗 | 点了做什么 |
| --- | --- | --- |
| ◧ 收起按钮 | 能 | 隐藏或恢复文档列表 |
| 正文段落、标题、表格与图块 | 能 | 原位置显示该块源码，离开后恢复预览 |
| 分组标题行（FEATURE 3） | 能 | 展开或折叠这个分组 |
| 文件夹图标 | 能 | 只展开或折叠这个目录，保留右栏当前页面 |
| 文档包标题、◇ Use Case、◻ 页面行 | 能 | 在右栏打开这一页；文档包标题打开它的 README 并展开；没有 README 的目录标题切换展开状态 |
| 横幅里的 finding、⚗ 测试与 ⟨⟩ 代码行 | 能 | 在正文下方打开那个位置的只读源码 |
| 正文里的链接 | 能 | 打开链接的页面；概念链接弹出定义卡片 |
| 仓库地址、页面路径、步骤名、“守护它的测试”等小标题 | 不能 | 没有悬停效果，也不显示手形指针 |

## 文档列表

分组与[文档模型](../../document-model.md)的分组一致，所以 Feature 以外的文档也都在列表里，不用离开 mod 去终端找：

| 分组 | 包括 |
| --- | --- |
| Feature | `docs/feature/` 下的文档包 |
| Engineering | `docs/engineering/` 下的文档包：构建、测试、性能测量、发版等开发本项目的能力 |
| Roadmap | `docs/roadmap/` 下还没开始实现的方向 |
| 项目规则 | 品味 `docs/taste.md`、写作规则 `docs/writing.md`，以及每一份术语表 `concepts.md`，术语表显示它的标题 |
| Design | `docs/design/` 下还没定下来的取舍 |
| Issue | `docs/issues/` 下还要处理的 Issue |
| Memory | `memory/` 下的经验 |
| 其它文档 | 项目入口 `docs/README.md`、`docs/architecture.md`、`docs/document-model.md`，以及从已列出页面的正文链接可以到达、不属于上面分组的 Markdown |

- 每个分组的标题行只显示分组名和页数，整行点击展开或折叠，不显示箭头或预留箭头的位置。Feature 与 Engineering 默认展开，其余默认折叠；打开的页面所在的分组自动展开。没有页面的分组不显示。mod 不扫描任意 Markdown。
- 文档包与种类目录（例如 `architecture/`）一行只显示文件夹图标与标题。文件夹图标按展开状态显示打开或关闭的形态，点击只展开或折叠，保留右栏当前页面；点标题打开它的 `README.md` 并展开，没有 README 时切换展开状态。包内的 `README.md` 不另起一行，包节点本身就是它。文档包默认折叠，打开的页面所在的包自动展开。
- 文档树不显示展开箭头，也不为箭头留空列。文件夹与文件使用不同图标，同层的图标和标题对齐，子层仅用缩进表达层级。
- 刷新、换页、收起文档列表与改变面板宽度都不改变展开状态。
- 每一行显示标题，不显示路径；放不下时截断。页面的种类（README、Use Case、cli、architecture 等）只决定图标，未知种类按普通页面显示。
- 文档列表还没取到时显示 `dim` 色的“正在读取文档…”。

## 页面视图

- 顶栏下面只显示 `dim` 色、可截断的页面路径与保存状态。没有编辑、保存、取消与格式按钮；正在保存、保存失败和检查问题用文字表达。
- 正文四周留 12px 边距，可滚动：Markdown 按主题渲染，图片与 Mermaid 图显示成图，宽度不超过正文（渲染方式见[正文渲染](architecture.md#正文渲染)）。
- 正文采用[原位预览](architecture.md#原位预览)：点击块后只在该位置展开源码输入，其它块保持排版。停止输入 800ms 自动保存，失焦立即保存并恢复预览；图形的渲染错误显示在所属块内，仍可点击修正。块外原文不被重写。
- p5 图解显示文字说明与源码，以及“在浏览器中播放”。
- 检查有问题时在路径行下面显示 `blocked` 色的“N 个问题”，每个 finding 一行：等宽的 `路径:行` 与说明，点一行打开那个位置的源码。检查通过只显示状态文字。页面被删除时显示“这页已被删除”。后台更新直接重载，没有冲突、合并与仓库切换确认。
- Use Case 正文下方隔一条分隔线，列出“守护它的测试”与“实现它的代码”，按步骤分组，步骤名是小标题。每项一行：图标、名称和 `dim` 色的 `路径:行`；点一项，在正文下方打开那个位置的只读源码，带标题和关闭按钮。
- 点正文里的概念链接，在正文上方显示一张 `raised` 底色的卡片：术语、定义和它所在的 `concepts.md`，右上角是关闭按钮。

## 出错时

- 已经显示文档时出错，在顶栏下方显示一条横幅：`blocked` 色的错误消息，右边是“复制给 agent”与关闭按钮；“复制给 agent”复制[交给 agent](#交给-agent)的请求，原始输出就在请求里。错误不混进正文，正文与文档列表保持原样。
- 界面上不直接显示原始的进程输出或异常文本。CLI 返回具名错误时显示它的消息；无法识别的失败显示“Concord 命令失败”。
- 下一次成功读取时横幅自动消失。

## 状态页

还不能显示文档时，mod 只显示一张状态页，不显示文档列表。内容在面板中部成一列，最宽 360px，左对齐：第一行是标题，用一句话说出发生了什么；第二行用 `muted` 色说明在哪里或为什么；要人处理的事是一段[交给 agent](#交给-agent)的请求；需要 mod 执行的操作是一个主按钮。一页最多一个主按钮。

| 情形 | 标题 | 第二行 | 操作 |
| --- | --- | --- | --- |
| 当前 tab 没有终端，或终端还没报告目录 | 先在这个 tab 里打开一个终端 | 终端报告目录后，Concord 会自动跟随 | 无 |
| 终端不在 Git 仓库里 | 这里不是 Git 仓库 | 终端的目录 | 提示“在终端里 `cd` 到一个 Git 仓库，mod 会跟着切换” |
| 连不上终端所在的机器 | 连不上 <机器> | Herdr 恢复连接后自动重试 | 无 |
| 正在检测命令行工具 | 正在检测 Concord 命令行工具… | 仓库地址 | 无 |
| 没有 Concord | 这个 mod 需要 Concord 命令行工具（远程为“<机器> 上没有 Concord 命令行工具”） | 让 agent 装好后，mod 自动继续 | 交给 agent：安装 Concord |
| Concord 不认识 mod 用到的命令 | Concord 版本过旧（远程为“<机器> 上的 Concord 版本过旧”） | 它不认识的命令 | 交给 agent：升级 Concord |
| mod 打开后第一次读取这个仓库 | 正在读取 Concord 仓库… | 仓库地址 | 无 |
| 仓库还没有初始化 | 这个仓库还没有初始化 Concord | 仓库地址 | 主按钮“在这里初始化 Concord” |

命令报告仓库还没有初始化（`ProjectNotInitialized`）时就是最后一行，不当作错误显示。其它错误发生在第一次读取时，标题是错误的消息，第二行是仓库地址，下面是交给 agent 的请求。

mod 不比较版本号：它直接运行需要的命令，只有 Concord 回答不认识某个命令时才显示版本过旧。没有 Concord 或版本过旧时，mod 每 2 秒在那台机器上重新检测一次，装好后自动继续，不需要再点什么。

## 交给 agent

要人处理的事交给身边的 agent（[要人处理的事，交给 agent](../../taste.md#t-15)）。mod 显示一段请求，用户复制后贴给 agent：

- 请求是一个等宽字体的块，可以选中；旁边是主按钮“复制给 agent”，点一下把整段放进剪贴板，按钮短暂显示“已复制”。
- 请求写明机器与仓库地址、发生了什么、要达到什么结果；有具名错误时带错误名与消息。有原始输出时，复制的内容在最后附上它，界面上的块只显示一行“复制时附上原始输出（N 行）”，不把进程输出摊在页面上。
- mod 不替用户把请求发给哪个终端：用户自己决定交给哪个 agent。

没有 Concord 时的请求（以下为预期输出）：

```text
在 vps 上安装 Concord 命令行工具：运行
curl -fsSL https://github.com/CorrectRoadH/Concord/releases/latest/download/install.sh | sh
然后用 concord --version 确认能运行。
```

命令报错时的请求（以下为预期输出）：

```text
Concord 在 ~/code/shop 报错：ConfigurationInvalid：配置需要修正。
请找出原因并修好；修好后 Concord mod 会自动恢复。

复制时附上原始输出（12 行）
```

## 刷新时不闪

后台刷新只在结果变化时改变界面，并且一次换上：

- 重新读取期间，状态页、文档列表、正文和按钮都保持原样；新结果就绪后一次替换。没有变化就什么也不动。
- “正在读取 Concord 仓库…”、“正在读取文档…”与“正在渲染页面…”只在 mod 打开后第一次读取这个仓库、第一次打开这一页时出现。
- 切回最近看过的仓库，立即显示离开时的文档列表、页面、滚动位置与展开状态，再在后台刷新；最多记住最近的 8 个仓库，更早的按第一次读取处理。
- 刷新后结论不变（例如仍然没有初始化），页面和按钮不重画成别的样子，按钮也不暂时消失。
