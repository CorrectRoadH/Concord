# Concord mod 的界面

mod 的外观与 Herdr 自带的 Files、Changes 一致，看起来是 Herdr 的一部分，而不是一张网页。

## 外观

- 整个面板是一张卡片：`background` 底色、1px `border` 边框、10px 圆角。颜色一律取主题的颜色名，不写死色值，换主题时跟着变。正文 13px，路径与说明 12px，小标题与计数 11px。
- 顶栏高 42px，下面一条 `border` 分隔线。左边是粗体的“Concord”，接着是 `dim` 色、放不下时截断的仓库地址：本机显示以 `~` 缩写的路径，远程显示 `<机器>:<路径>`。右边不放按钮：mod 用来读 Spec，新建文档在和 agent 的对话里完成。
- 能点的东西看起来就能点：行高 28px、7px 圆角，悬停时 `hover` 底色并显示手形指针，当前打开的页面用 `selected` 底色。不能点的小标题（例如“守护它的测试”、步骤名）是 11px、`dim` 色，没有悬停效果，和可点的行一眼可分。
- 按钮高 28px，宽度随文字。主按钮用 `solid` / `solid_foreground`，一屏最多一个；其它按钮是带 `border` 边框的次按钮。正在执行的按钮显示进行中的文字（例如“正在保存…”），执行期间不能再点。
- 图标是随 mod 分发的 Lucide 线条图标（ISC 许可，写入 `NOTICE.txt`），按文字颜色着色：展开箭头、文件夹、文档、Use Case、测试、代码、收起与关闭。
- 文件位置（`路径:行`）与代码用 Herdr 设置里的等宽字体。

## 双栏

面板始终是两栏：左边是文档列表，右边是页面，中间一条 `border` 分隔线。布局侧栏常常只有四五百像素宽，所以文档列表的宽度是面板宽度的 40%，介于 160px 与 240px 之间；页面占其余宽度。

顶栏最左边是收起按钮：点一下隐藏文档列表，页面占满面板，再点一下恢复。收起状态在刷新、换页与换仓库时保持。还没有打开页面时，右栏用 `dim` 色显示“选一页开始阅读”。

下面的线稿是约 480px 宽的侧栏。方括号是按钮；带箭头或图标的行可以点；路径、小标题和正文文字不能点。

```text
┌──────────────────────────────────────────────────────────────┐
│ ◧  Concord  ~/code/shop                                      │ 顶栏 42px
├───────────────────┬──────────────────────────────────────────┤
│ ▾ FEATURE  3      │ docs/feature/cart/README.md      [编辑]  │ 工具行
│ ▾ ▣ 购物车        │┃ 1 个问题                                 │ 检查横幅
│     ◇ 加入商品    │┃ docs/feature/cart/README.md:12  单子→订单│ ← 可点
│     ◻ 架构        │                                          │
│ ▸ ▣ 结算          │  # 购物车                                │ 正文
│ ▾ ENGINEERING  2  │  把商品放进购物车，数量自动合并……        │
│ ▸ ▣ 构建          │                                          │
│ ▸ 项目规则  3     │ ──────────────────────────────────────── │
│ ▸ ISSUE  1        │ 守护它的测试                             │
│                   │  open-feature                            │ 步骤名
│                   │   ⚗ adding the same sku…  cart.test.js:1 │ ← 可点
│                   │ 实现它的代码                             │
│                   │   ⟨⟩ addItem              src/cart.js:8  │ ← 可点
└───────────────────┴──────────────────────────────────────────┘
```

| 元素 | 能点吗 | 点了做什么 |
| --- | --- | --- |
| ◧ 收起按钮 | 能 | 隐藏或恢复文档列表 |
| `[编辑]` 等方括号按钮 | 能 | 按钮上写的操作 |
| 分组标题行（▾ FEATURE 3） | 能 | 展开或折叠这个分组 |
| 文档包前的 ▸ / ▾ 箭头 | 能 | 只展开或折叠这个包 |
| ▣ 文档包、◇ Use Case、◻ 页面这类带图标的行 | 能 | 在右栏打开这一页；文档包打开它的 README 并展开 |
| 横幅里的 finding、⚗ 测试与 ⟨⟩ 代码行 | 能 | 在正文下方打开那个位置的只读源码 |
| 正文里的链接 | 能 | 打开链接的页面；概念链接弹出定义卡片 |
| 仓库地址、页面路径、步骤名、“守护它的测试”等小标题 | 不能 | 没有悬停效果，也不显示手形指针 |

## 文档列表

分组与[文档模型](../../document-model.md)的分组一致，所以 Feature 以外的文档也都在列表里，不用离开 mod 去终端找：

| 分组 | 包括 |
| --- | --- |
| Feature | `docs/feature/` 下的文档包 |
| Engineering | `docs/engineering/` 下的文档包：构建、测试、性能测量、发版等开发本项目的能力 |
| Roadmap | `docs/roadmap/` 下还没开始实现的方向 |
| 项目规则 | 品味 `docs/taste.md`、写作规则 `docs/writing.md`，以及每一份术语表 `concepts.md`，术语表显示它的标题 |
| Design | `docs/design/` 下还没定下来的取舍 |
| Issue | `docs/issues/` 下还要处理的 Issue |
| Memory | `memory/` 下的经验 |
| 其它文档 | 项目入口 `docs/README.md`、`docs/architecture.md`、`docs/document-model.md`，以及从已列出页面的正文链接可以到达、不属于上面分组的 Markdown |

- 每个分组的标题行是一个可折叠的节点：展开箭头、分组名和页数。Feature 与 Engineering 默认展开，其余默认折叠；打开的页面所在的分组自动展开。没有页面的分组不显示。mod 不扫描任意 Markdown。
- 文档包与种类目录（例如 `architecture/`）也是可折叠的节点：一行显示展开箭头、图标与标题。点箭头只展开或折叠；点标题打开它的 `README.md` 并展开。包内的 `README.md` 不另起一行，包节点本身就是它。文档包默认折叠，打开的页面所在的包自动展开。
- 刷新、换页、收起文档列表与改变面板宽度都不改变展开状态。
- 每一行显示标题，不显示路径；放不下时截断。页面的种类（README、Use Case、cli、architecture 等）只决定图标，未知种类按普通页面显示。
- 文档列表还没取到时显示 `dim` 色的“正在读取文档…”。

## 页面视图

- 顶栏下面是页面的工具行：左边是 `dim` 色、可截断的页面路径；右边是“编辑”。编辑时换成“放弃修改”与主按钮“保存并检查”。
- 正文四周留 12px 边距，可滚动：Markdown 按主题渲染，图片与 Mermaid 图显示成图，宽度不超过正文（渲染方式见[正文渲染](architecture.md#正文渲染)）。
- 编辑时编辑器占满工具行下面的全部高度。
- p5 图解显示文字说明与源码，以及“在浏览器中播放”。
- 检查结果是工具行下面的一条横幅：通过时是 `done` 色的“检查通过”；有问题时是 `blocked` 色的“N 个问题”，下面每个 finding 一行：等宽的 `路径:行` 与说明，点一行打开那个位置的源码。保存冲突、页面已被删除、终端已切到别的仓库也用同样的横幅，横幅里带它的操作按钮。
- Use Case 正文下方隔一条分隔线，列出“守护它的测试”与“实现它的代码”，按步骤分组，步骤名是小标题。每项一行：图标、名称和 `dim` 色的 `路径:行`；点一项，在正文下方打开那个位置的只读源码，带标题和关闭按钮。
- 点正文里的概念链接，在正文上方显示一张 `raised` 底色的卡片：术语、定义和它所在的 `concepts.md`，右上角是关闭按钮。

## 出错时

- 已经显示文档时出错，在顶栏下方显示一条横幅：`blocked` 色的错误消息，右边是关闭按钮；有原始输出时多一个“详情”，点开以等宽字体显示。错误不混进正文，正文与文档列表保持原样。
- 不显示原始的进程输出或异常文本。CLI 返回命名错误时显示它的消息；无法识别的失败显示“Concord 命令失败”，原始输出折叠在“详情”下。
- 下一次成功读取时横幅自动消失。

## 状态页

还不能显示文档时（检测 CLI、缺少或过旧的 CLI、没有终端、不是 Git 仓库、连不上机器、还没有初始化），mod 只显示一张状态页，不显示文档列表：

- 内容在面板中部成一列，最宽 360px，左对齐。
- 第一行是标题，用一句话说出发生了什么，例如“这个仓库还没有初始化 Concord”。
- 第二行用 `muted` 色说明在哪里或为什么：仓库路径、机器名或缺少的版本。
- 需要用户在终端运行的命令放在代码块里，可以选中复制；需要 mod 执行的操作是一个主按钮。一页最多一个主按钮。
- 状态页只在结论变化时切换。“正在读取”只在第一次读取这个仓库时出现；之后的后台重新读取保持当前页面和按钮不动，不闪烁。
- 命令报告仓库还没有初始化（`ProjectNotInitialized`）就是“还没有初始化”这一页，不当作错误显示。
