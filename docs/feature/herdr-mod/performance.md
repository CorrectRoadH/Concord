# Concord mod的性能测量

本页拥有 herdr-mod 的测量场景与预算，方法见[性能测量](../../engineering/performance/README.md#测量方法)。场景直接使用 Mitata，入口为 `bench/herdr-mod.bench.ts`。

## 测量场景

| 场景 | 测量内容 |
| --- | --- |
| `herdr-mod/page-source` | 解析实际页面正文中的文本与特殊内容块 |

计时边界为进程内真实操作与其自身资源释放，排除 CLI 宿主启动和格式化。固定输入、消费者与缓存状态由场景源码声明；修改这些条件时重新建立参照结果，不使用整进程数字作为操作预算。

Mitata 的成功退出表示测量完成，预算由交付者对照适用条件与原生统计判断。没有相同边界的参照证据时只报告测量结果，不宣称预算通过。

## 用户可见目标

页面模型解析不证明真实 Herdr 的加载、切换或推送时间。已初始化仓库的首屏与切入新仓库目标为 300ms，切回页面目标为 50ms，文件停止写入到可读描述更新的目标为 1000ms。它们需要真实事件边界的独立证据，不能用 `page-source` 的结果替代。

## CLI 交互测量 {#cli-interactions}

使用真实 CLI 与隔离的接入项目，测量 mod 会话首屏刷新、切换到另一仓库的刷新，以及文件保存至读回确认的耗时。场景分别为 `herdr-mod/first-refresh`、`herdr-mod/switch-repository` 与 `herdr-mod/save-confirmation`，由 `bench/herdr-mod.bench.ts` 注册。

固定两个已初始化的仓库，每个包含一篇约 4 KiB 的 Feature，服务在测量前预热。首屏从新建会话发起刷新计时，到文档列表可读结束；切换从选择另一个仓库会话计时，到其列表可读结束。保存从提交不同正文开始，到读回确认且 `saving` 解除结束，不计后台全仓检查。

样本使用真实 ModSession 与公开 CLI，宿主只替换进程执行边界，不复制产品逻辑。临时仓库、预热与清理不计入操作耗时；结束后停止各自服务并删除临时文件。不得复用其它测试或用户服务。

这些结果包含 CLI 启动与 IPC，排除 GPUI 绘制和远程网络；不能据此声称满足真实桌面的首屏或切换目标。没有同机同输入基线时报告原生统计，不声明优化倍数或用户可见预算通过。
