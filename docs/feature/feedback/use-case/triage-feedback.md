# 将外部反馈关联到项目调查与功能

维护者建立 GitHub 仓库或 Linear team 连接，导入一个 issue URL 或显式同步连接范围，浏览反馈后关联 Feature 和 Memory，编辑本地笔记并记录关闭理由。

## 主流程

1. 在项目设置的反馈来源中保存连接 ID、来源范围与读取方式。API 连接使用凭据环境变量名；GitHub gh 连接复用服务端机器的 CLI 登录态，不保存凭据变量或密钥。缺省仍为 API。首次完整同步成功时持久绑定远端范围身份，连接检测不绑定。
2. 明确触发导入或同步；读取在仓库写锁外完成。分页只是一次有界遍历，不承诺某一瞬间的完整快照。
3. 同一来源对象只有一条本地反馈；换连接或清空缓存后再次导入也不重复创建。
4. 在反馈详情分别查看首次来源摘录、缓存的远端观察和本地 Markdown 笔记。更新远端数据不改本地标题、正文或关闭状态。
5. 关联 Feature 或 Memory；关闭反馈仍遵守关联未关闭 Problem 的门禁。

## 验收

- GitHub 使用 REST issue ID；Linear 使用组织与 issue UUID。名称、显示编号、标题和连接 ID 都不是去重身份。
- GitHub 列出所有状态并排除 PR；Linear 包含归档项。任一页失败、GraphQL errors 或超出遍历上限均不发布部分反馈。
- 连接范围变化或读取期间项目配置变化明确失败，保留原文档。
- dry-run 不写文档和缓存。缓存可清空或损坏，持久来源、本地笔记与关系仍可读。
- 缓存不以较旧 updatedAt 覆盖较新观察；相同版本但内容不一致保留旧值并报告冲突。
- Web 与 CLI 都可创建本地反馈、配置连接、导入、同步、关联和关闭；Web 普通刷新不请求外部服务。
- Web 反馈列表保留来源与处理状态筛选，低频来源字段在详情中展开。详情的「来源与关联」页签展示首次来源快照、上次观察缓存和 Feature 关联；正文仅编辑本地笔记。切换到来源页签先完成草稿保存，冲突时保留草稿；Memory 关系与关闭继续在生命周期维护。
- 连接的添加、移除和配置入口归项目设置，反馈页提供设置链接以及已配置来源的同步／导入入口；无远端来源仍可创建本地反馈。空集合不显示无作用的筛选，筛选无结果保留筛选条件。项目设置的来源视图可通过 URL 直接打开，与配置表单及高级表示共用同一配置摘要和草稿保护；修改其它设置不得覆盖并发新增或删除的来源。
- gh 连接只在显式检测、同步或导入时启动 CLI；正常页面刷新和配置保存不读取远端。检测先完成当前配置保存，冲突阻止检测；移除或切换连接后，旧请求结果不能覆盖当前状态。API 与 gh 之间切换保留绑定和去重身份，不自动回退或重建反馈。
- CLI 同步与检测共用单个进程槽位；响应未完成时断连取消读取，服务关闭等待进程收尾或已开始的发布事务。读取失败、预算超限、取消或清理未确认均不得发布部分反馈；清理未知时禁止继续启动 CLI 读取。
- 密钥值不进入项目文档、浏览器响应或诊断。测试只模拟外部 HTTP 或进程边界，不调用真实账号；Concord 的身份验证、资源回收和发布流程实际执行。

反馈以常驻内容导航作为选择入口，搜索、来源与处理状态筛选紧邻条目列表。点击条目后列表仍保留，右侧显示该反馈的正文、来源与关联及生命周期；不要求返回列表才能选择另一条。移动端使用共享内容导航抽屉，选择后关闭抽屉；切换反馈继续遵守正文保存和冲突保护。无反馈、筛选无结果和反馈不存在分别呈现。来源设置、导入与同步仍须用户明确触发，选择反馈不读取远端。
