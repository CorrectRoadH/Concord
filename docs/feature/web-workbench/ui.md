# 工作台界面

本页声明工作台的布局、交互状态、视觉层级与界面验收。功能概览见 [README](README.md)，各操作的完整路径见 [Use Case](use-case/use-web-workbench.md)，URL 状态、组件与样式变量的实现见[工作台架构](architecture.md)（[一件事只写一次](../../taste.md#t-3)、[读得懂胜过写得全](../../taste.md#t-1)）。

## 原则

1. 内容优先。用户打开页面首先看到正在维护的对象和正文，导航只占完成选择所需的宽度。
2. 层级靠位置与留白，不靠边框。重复条目用轻分隔线，只有独立操作区域才使用面板。
3. 一处一个入口。同一操作在同一视图只保留一个主要入口，已有上下文时不重复标题和说明。
4. 没有内容就不占位。空页签、空操作面板、无作用的筛选栏不渲染。
5. 有效信息不能被简化掉。错误、保存冲突、健康诊断和来源读取失败始终清晰可见。

## 导航

主侧栏显示 Feature、Roadmap、Design、Engineering、Memory 等分类入口，以及「文档」。独立的第二侧栏始终显示当前分类的完整条目列表及筛选输入；点击条目只切换右侧预览，列表不会消失。分类入口默认预览第一项，空集合提供创建入口，不重复展示卡片网格。

支持页面与 Use Case 在右侧预览内访问，移动端通过单独的内容导航抽屉访问条目列表。点击 Use Case 时保留 Feature 背景，并从右侧打开详情抽屉；深链接和刷新仍打开该抽屉。关闭或返回时先完成待保存内容，只有自动保存失败时才要求处理草稿。

文档、写作、术语、反馈与 Git 复用同一个内容导航。反馈的第一入口是反馈条目，Git 的第一入口是变更文件。写作与术语先选择适用范围，再显示该范围的规则或术语；主导航不藏进设置折叠项或额外管理入口。

## 页面结构

桌面最多同时出现三列：工作区侧栏、内容导航、主内容。包内文件树属于主内容的一部分，不能再形成第四列。

| 区域 | 宽度 | 内容 |
| --- | --- | --- |
| 工作区侧栏 | 固定，可折叠 | Feature、Design、文档、Git、反馈、设置等分类入口 |
| 内容导航 | 240–300px | 当前分类的条目列表、筛选、新建入口 |
| 主内容 | 剩余宽度 | 对象标题、页签、正文或记录列表 |
| 包内文件树 | 200–240px，位于主内容左侧 | 仅在对象有多个文件时出现 |
| 详情抽屉 | 桌面 560–720px，手机全屏 | Use Case、源码等临时上下文 |

主内容宽度小于 960px 时，包内文件树收进正文上方的「文件」下拉或折叠区，不与正文并排。手机端内容导航使用抽屉，工具栏允许换行，长路径不撑宽页面。

操作按作用范围放置：

| 层级 | 位置 | 例子 |
| --- | --- | --- |
| 集合操作 | 内容导航标题旁 | 新建 Feature |
| 对象操作 | 对象标题行右侧 | 查看 Git 变更 |
| 页签操作 | 页签内紧凑工具栏 | 添加关联、运行 |
| 条目操作 | 条目行内独立控件 | 打开源码、取消运行 |
| 低频细节 | 展开详情或菜单 | ID、完整引用、复制路径 |

## 视觉基础

### 颜色

颜色全部来自工作台主题，明暗主题的信息层级一致。页面背景不加包围整个内容区的边框；独立面板与背景只有轻微差异，最多一层。分隔线不得使用正文色或近白色；焦点环不随装饰边框一起减弱。

黄色只表示告警、待处理或需要注意，不作为分类装饰。错误色用于解析失败、保存冲突与加载失败。普通权限说明和保存方式说明使用次级文字，不使用常驻告警卡片。

### 字号与正文

| 元素 | 规格 |
| --- | --- |
| 页面标题 | 24–28px，由共享样式统一，不逐页覆盖 |
| 页签工具栏标题 | 18px |
| 分组标题、条目主名称 | 14–16px |
| 界面文字 | 14px，行高 1.55 |
| Markdown 正文 | 约 15.5px，行高 1.75，行宽不超过 850px 并居中 |
| 正文标题 | H1 2em、H2 1.5em、H3 1.25em，标题上方留白大于下方 |

分组靠间距和位置区别于条目，不靠不断放大字号。次级信息保持可读，长路径允许换行；代码块与源码保持等宽字体和横向滚动，不自动折行。

### 间距与表面

| 元素 | 规则 |
| --- | --- |
| 功能分组 | 标题与统计同一行，组间 24–32px |
| 重复记录 | 上下内边距 12–16px，1px 低对比度横线分隔，不逐条套圆角卡片 |
| 独立表单或摘要 | 内边距 16–24px，无常驻重阴影 |
| 输入框、按钮 | 保留可识别控件边界，和内容分隔线分别调整 |
| 抽屉、弹窗 | 独立表面加遮罩 |

页签内容不额外增加顶部外边距。新建与添加操作统一使用 outline 按钮。

## 页面模式

### 文档阅读

正文默认以排版后的 Markdown 阅读，元数据与完整原文放在可展开详情里。阅读与编辑有明确入口和状态文字。编辑器不支持某段语法时，可正常阅读的正文不能退化成整屏源码。

包内文件树遵守以下规则：

- 不使用卡片边框，与正文之间用留白或一条竖向分隔线区分。
- 文件夹行显示目录名，点击文件夹行打开该目录的 `README.md`，展开箭头单独负责折叠；目录内不再重复列出 `README.md`。包目录与种类目录（例如 `architecture/`）遵守同一规则；种类目录内的叶子页面可以深链接，刷新后仍打开该页面。
- Engineering 包内的种类目录与 Feature 相同，不因此开放测试页签。
- 默认只展开当前文件的祖先目录，其它目录折叠。
- 叶子只显示文件名，完整路径放在悬停说明和当前文档上下文里，不逐行换行显示完整路径。
- 搜索命中保留祖先层级。

`docs/` 文档导航和包内文件树使用同一套缩进、图标和选中底色。图标不能是唯一可辨认的标签。

### 对象页签

页签和可用操作由[工作台 Spec](README.md)定义。内容按自然高度纵向排列，不强制左右等高卡片。危险动作单独分区，确认、证据与授权要求由对应操作的 Spec 定义。

### 实现与测试

实现页直接按功能名称分组，不加「Feature 公共实现」「Use Case ·」等前缀。

```text
实现                                      ＋ 添加关联

Agents 与 Adapters                         18 处 · 13 个文件
────────────────────────────────────────────────────────
  aiSdkAgent                                  类／函数
  packages/…/agents/ai-sdk.ts                   L490–572
  关联 Spec
────────────────────────────────────────────────────────
```

示意中的路径省略只为排版，页面应能读到完整路径。条目展示符号名、范围类型、路径、行号和关联 Spec，不显示声明 ID。宽内容区分两列，窄内容区单列堆叠。点击源码位置打开抽屉，其它操作保留独立控件。多对多关系允许同一代码出现在多个分组，各组统计只描述本组。

测试页沿用同样的记录结构，不设内部页签、搜索框和计数工具栏；运行、取消和最近任务状态留在条目内。命令收据不能被设计成原生测试覆盖证明。

### 反馈与设置

反馈页以反馈列表和处理操作为主体。内容导航放标题、搜索、来源和状态筛选；右侧只显示操作区和所选内容。条目以标题、本地处理状态和来源为主要信息，更新时间为次级信息，本地状态与远端状态分别标识。同步状态靠近操作入口，不另起大卡片。

来源配置放在项目设置，目标仓库或团队为主信息，运行环境和连接状态为次级信息。未安装、未登录、无权限等状态给出简短具体的操作提示。

### 写作、术语与 Git

导航名称使用用户任务：写作规则、术语、适用范围。全局范围显示「整个项目」，目录路径作为次级来源信息，继承显示为「沿用上级规则」。界面不展示「政策／概念」等内部 owner 类型。

这些页面已有内容导航标题，右侧不再重复页面标题和介绍。Git 的分类页签位于内容导航标题下、文件列表上方。

## 自动保存

正文、源码、元数据和项目设置停止输入 800ms 后自动保存，同一编辑器的请求串行执行；请求期间的新输入留给下一次保存。切换预览、页签、文件或关闭详情抽屉前先完成保存。创建、运行测试和生命周期裁决是显式操作。自动保存写入 Git 工作树，不执行暂存、提交或 push。

保存使用整文件摘要，只用于防止覆盖并发的外部编辑，不是授权边界；冲突保留草稿并展示差异。通用保存可以写入任何受管文件，与在工作台以外直接编辑相同。修复核验另有表单，执行需要运行的步骤并写入结果。

## 验收

视觉验收使用真实浏览器截图和计算样式，不只检查变量声明。`pnpm check` 验证构建、类型和打包消费者行为，不能替代视觉验收。

- 数据量：无数据、单条、18 条以上记录。
- 视口：390px 手机、1280px 桌面、宽屏桌面。
- 主题：明暗主题的信息层级一致，描边不继承正文色。
- 交互：键盘焦点、详情展开、源码定位与关闭返回。
- 结构：长列表能辨认条目边界，没有连续的亮白矩形框；空页签和空操作面板不占空间；文档在 1280px 下正文行宽不小于 600px。
