# 工作台界面

本页声明工作台的布局、交互状态、视觉层级与界面验收。功能概览见 [README](README.md)，各操作的完整路径见 [Use Case](use-case/use-web-workbench.md)，URL 状态、组件与样式变量的实现见[工作台架构](architecture.md)（[一件事只写一次](../../taste.md#t-3)、[读得懂胜过写得全](../../taste.md#t-1)）。

## 原则

1. 内容优先。用户打开页面首先看到正在维护的对象和正文，导航只占完成选择所需的宽度。
2. 层级靠位置与留白，不靠边框。重复条目用轻分隔线，只有独立操作区域才使用面板。
3. 一处一个入口。同一操作在同一视图只保留一个主要入口，已有上下文时不重复标题和说明。
4. 没有内容就不占位。空页签、空操作面板、无作用的筛选栏不渲染。
5. 有效信息不能被简化掉。错误、保存冲突、健康诊断和来源读取失败始终清晰可见。

## 导航

主侧栏显示 Feature、Roadmap、Design、Engineering、Memory 等分类入口，以及「文档」。独立的内容导航始终显示当前分类的完整条目列表及筛选输入；点击条目只切换右侧预览，列表不会消失。分类入口默认预览第一项；默认只在 URL 还没有选择时生效，用户在默认项打开前点击的条目不被它覆盖。空集合提供创建入口，不重复展示卡片网格。

附页与 Use Case 在右侧预览内访问，移动端通过单独的内容导航抽屉访问条目列表。点击 Use Case 时保留 Feature 背景，并从右侧打开详情抽屉；深链接和刷新仍打开该抽屉。关闭或返回时先完成待保存内容，只有自动保存失败时才要求处理草稿。

文档、写作、术语、反馈与 Git 复用同一个内容导航。反馈的第一入口是反馈条目，Git 的第一入口是变更文件。写作与术语先选择生效范围，再显示该范围的规则或术语；主导航不藏进设置折叠项或额外管理入口。

内容导航在桌面常驻；手机选中对象后关闭内容抽屉。反馈切换条目时保留保存保护。Git 切换文件时保留目录展开、状态、分类、区域与新增测试行定位。在列表里切换只改变右侧对象，不触发运行、同步或提交。

文档集合的新建入口属于内容导航，放在桌面侧栏与手机内容导航的工具栏；详情工具栏只放当前对象的操作。项目侧栏与总览用 worktree 的目录名称呼项目。

### 路径菜单

文档侧栏、支持文件树、Git 文件树和关联文件条目上右键打开路径菜单。菜单分别复制相对仓库根的路径，以及 View 服务端所在机器上的绝对路径；目录复制自身路径。

- 菜单操作不导航、不保存，也不折叠节点。
- 复制成功与浏览器拒绝分别提示；路径来自服务端仓库，不取浏览器所在机器的路径。
- 键盘可以打开和关闭菜单。

### URL 与导航

每个页面的 tab、当前文件、Use Case 与源码抽屉、Git 展示模式都从 URL 得到，浏览器不另存导航副本。前进、后退、刷新和直接打开都回到对应位置；未提供或无效的选择按页面能力回落到默认值。

导航前先保存唯一活动编辑器的最新草稿，见[自动保存](#自动保存)。

## 页面结构

桌面最多同时出现三列：主侧栏、内容导航、主内容。文档包文件树属于主内容的一部分，不能再形成第四列。

| 区域 | 宽度 | 内容 |
| --- | --- | --- |
| 主侧栏 | 固定，可折叠 | Feature、Design、文档、Git、反馈、设置等分类入口 |
| 内容导航 | 240–300px | 当前分类的条目列表、筛选、新建入口 |
| 主内容 | 剩余宽度 | 对象标题、页签、正文或记录列表 |
| 文档包文件树 | 200–240px，位于主内容左侧 | 仅在对象有多个文件时出现 |
| 详情抽屉 | 桌面 560–720px，手机全屏 | Use Case、源码等临时上下文 |

主内容宽度小于 960px 时，文档包文件树收进正文上方的「文件」下拉或折叠区，不与正文并排。手机端内容导航使用抽屉，工具栏允许换行，长路径不撑宽页面。

操作按作用范围放置：

| 层级 | 位置 | 例子 |
| --- | --- | --- |
| 集合操作 | 内容导航标题旁 | 新建 Feature |
| 对象操作 | 对象标题行右侧 | 查看 Git 变更 |
| 页签操作 | 页签内紧凑工具栏 | 添加关联、运行 |
| 条目操作 | 条目行内独立控件 | 打开源码、取消运行 |
| 低频细节 | 展开详情或菜单 | ID、完整引用、复制路径 |

## 视觉基础

### 颜色

颜色全部来自工作台主题，明暗主题的信息层级一致。页面背景不加包围整个内容区的边框；独立面板与背景只有轻微差异，最多一层。分隔线不得使用正文色或近白色；焦点环不随装饰边框一起减弱。

黄色只表示告警、待处理或需要注意，不作为分类装饰。错误色用于解析失败、保存冲突与加载失败。普通权限说明和保存方式说明使用次级文字，不使用常驻告警卡片。

### 字号与正文

| 元素 | 规格 |
| --- | --- |
| 页面标题 | 24–28px，由共享样式统一，不逐页覆盖 |
| 页签工具栏标题 | 18px |
| 分组标题、条目主名称 | 14–16px |
| 界面文字 | 14px，行高 1.55 |
| Markdown 正文 | 约 15.5px，行高 1.75，行宽不超过 850px 并居中 |
| 正文标题 | H1 2em、H2 1.5em、H3 1.25em，标题上方留白大于下方 |

分组靠间距和位置区别于条目，不靠不断放大字号。次级信息保持可读，长路径允许换行；代码块与源码保持等宽字体和横向滚动，不自动折行。

### 间距与表面

| 元素 | 规则 |
| --- | --- |
| 功能分组 | 标题与统计同一行，组间 24–32px |
| 重复记录 | 上下内边距 12–16px，1px 低对比度横线分隔，不逐条套圆角卡片 |
| 独立表单或摘要 | 内边距 16–24px，无常驻重阴影 |
| 输入框、按钮 | 保留可识别控件边界，和内容分隔线分别调整 |
| 抽屉、弹窗 | 独立表面加遮罩 |

页签内容不额外增加顶部外边距。新建与添加操作统一使用 outline 按钮。

## 页面模式

### 文档阅读

正文默认以排版后的 Markdown 阅读，元数据与完整原文放在可展开详情里。阅读与编辑有明确入口和状态文字。编辑器不支持某段语法时，可正常阅读的正文不能退化成整屏源码。

文档包文件树遵守以下规则：

- 不使用卡片边框，与正文之间用留白或一条竖向分隔线区分。
- 文件夹行显示目录名，点击文件夹行打开该目录的 `README.md`，展开箭头单独负责折叠；目录内不再重复列出 `README.md`。文档包目录与种类目录（例如 `architecture/`）遵守同一规则；种类目录内的叶子页面可以深链接，刷新后仍打开该页面。
- Engineering 文档包内的种类目录与 Feature 相同，不因此开放测试页签。
- 默认只展开当前文件的祖先目录，其它目录折叠。
- 叶子只显示文件名，完整路径放在悬停说明和当前文档上下文里，不逐行换行显示完整路径。
- 搜索命中保留祖先层级。

`docs/` 文档导航和文档包文件树使用同一套缩进、图标和选中底色。图标不能是唯一可辨认的标签。文件树同层的文件夹与文件图标和文字对齐，文件夹在前，同层按名称排序。

在同一 Feature 内切换页面时，文件树保留折叠与滚动状态。正文已滚动、长短文件互切时，加载中与加载后的工具栏和文件树位置保持不变。

「文档」中的参考模板按物理目录显示为可折叠树，叶子显示文件名。按标题或路径搜索时保留祖先层级并展开结果。深链接、刷新与前进后退展开当前文件的祖先，选中哪个文件仍由 URL 决定。桌面与手机导航提供相同的文件集合，折叠按钮可用键盘操作。

Memory 是单文件条目，同样在内容导航中选择，右侧预览正文，并提供元数据与生命周期入口。

### Markdown 呈现

阅读与编辑预览中的 Markdown 遵守以下规则。显示、主题与滚动变化都不改写 Markdown 字节。

- 相对链接以当前文件为基准解析，目录链接落到该目录的 `README.md`。已纳入工作区投影的文档与附页在工作台内导航，切换前先完成待保存草稿。外部 URL 由浏览器导航；越界或未知的目标不伪装成工作台页面。
- 代码块保持等宽字体与原始行，不自动折行，长行在块内横向滚动；Mermaid 源码同样如此。
- `$...$` 是行内公式，`$$...$$` 是独立公式，用随包的 KaTeX 与本地字体渲染，不访问 CDN。代码块与行内代码中的 `$` 保持字面量。渲染不启用信任扩展，保留 HTML 清理。错误公式在原处可见，不使整页失败；长公式在自身容器内滚动，深色主题下保持可读。
- 正文保留标题层级、段落间距与列表标记。表格带单元格边界与内边距，窄屏在表格内横向滚动。
- Mermaid 图默认显示预览，源码可展开编辑，展开与收起不修改文档。图的颜色跟随工作台主题，切换主题不重新渲染、不改变布局。源码无法解析时，图块内显示解析错误与行号并保留源码。
- 阅读视图识别 YAML frontmatter 与 HTML 锚点，元数据与原文可分别展开；编辑器不支持 HTML 时不显示编辑失败。阅读不写文件，不执行嵌入脚本或事件属性，品味条目链接和相对文档导航照常定位。
- 只有 p5 图块运行脚本，见[在 Markdown 中运行 p5 图块](use-case/embed-p5-sketch.md)。

### 对象页签

页签和可用操作由[工作台 Spec](README.md)定义。内容按自然高度纵向排列，不强制左右等高卡片。危险动作单独分区，确认、证据与授权要求由对应操作的 Spec 定义。

Feature 与 Use Case 的页签依次是「正文、术语、实现、测试、元数据」，Feature 另有「Use Cases」页签。Use Cases 页签放列表与新建入口，不放在正文下方；打开一个 Use Case 显示详情抽屉，关闭后回到 Use Cases 页签。

只有 Roadmap、Design、Memory 与 Issue 显示生命周期页签，内容是当前状态与实际可用的操作，不渲染空操作面板。没有状态转换的对象收到 `?tab=actions` 时显示元数据。路径与名称归入元数据。

### 实现与测试

实现页直接按功能名称分组，不加「Feature 公共实现」「Use Case ·」等前缀。

```text
实现                                      ＋ 添加关联

Agents 与 Adapters                         18 处 · 13 个文件
────────────────────────────────────────────────────────
  aiSdkAgent                                  类／函数
  packages/…/agents/ai-sdk.ts                   L490–572
  关联 Spec
────────────────────────────────────────────────────────
```

示意中的路径省略只为排版，页面应能读到完整路径。条目展示符号名、范围类型、路径、行号和关联 Spec，不折叠声明详情，不显示也不要求填写声明 ID。宽内容区分两列，窄内容区单列堆叠。点击源码位置打开抽屉，其它操作保留独立控件。多对多关系允许同一代码出现在多个分组，各组统计只描述本组。

分组以紧凑的源码列表与分隔线组织，不嵌套卡片。Feature 的实现页汇总 Feature 自身、附页与所属 Use Case 的关联。Engineering 详情使用同样的实现列表、添加关联与源码跳转，汇总主文档与附页的关联，但不开放测试页签。没有声明时引导接入，不用测试文件代替实现。

「添加关联」只选择 scope 与目标 Spec，生成可粘贴的注释，不含声明 ID，也不改写源码。

源码抽屉在桌面保持适合阅读的宽度，在手机占满屏幕。抽屉只显示一次文件路径，按真实行位置滚动到声明起始行并突出该行。源码带行号与随明暗主题变化的语法高亮，长行横向滚动；查看和定位不修改文件。

测试页沿用同样的记录结构，不设内部页签、搜索框和计数工具栏；运行、取消和最近任务状态留在条目内。测试只来自用户写在源码里的 Feature / Use Case 关联声明，统一显示为「测试」。命令证据不能被设计成原生测试覆盖证明。

### 反馈与设置

反馈页以反馈列表和处理操作为主体。内容导航放标题、搜索、来源和状态筛选；右侧只显示操作区和所选内容。条目以标题、本地处理状态和来源为主要信息，更新时间为次级信息，本地状态与远端状态分别标识。同步状态靠近操作入口，不另起大卡片。

来源配置放在项目设置，目标仓库或团队为主信息，运行环境和连接状态为次级信息。未安装、未登录、无权限等状态给出简短具体的操作提示。

反馈条目使用共享内容导航，证据使用共享记录列表。元数据与设置使用自然高度的字段分组和统一的保存状态。空集合、筛选无结果与对象不存在分别说明，不用大虚线框和搜索失败图标统一代替。

### 写作、术语与 Git

导航名称使用用户任务：写作规则、术语、生效范围。全局范围显示「整个项目」，目录路径作为次级来源信息，继承显示为「沿用上级规则」。界面不展示「政策／概念」等内部 owner 类型。

这些页面已有内容导航标题，右侧不再重复页面标题和介绍。Git 的分类页签位于内容导航标题下、文件列表上方。

术语页显示当前文档目录有效的 `concepts.md` 定义：服务端合成全局、祖先与显式直接导入的定义，页面显示完整来源与诊断。其它 Markdown 不作为结构化定义的来源。

## 自动保存

正文、源码、元数据和项目设置停止输入 800ms 后自动保存，同一编辑器的请求串行执行；请求期间的新输入留给下一次保存。切换预览、页签、文件或关闭详情抽屉前先完成保存。创建、运行测试和生命周期裁决是显式操作。自动保存写入 worktree 中的文件，不执行暂存、提交或 push。

保存使用整文件摘要，只用于防止覆盖并发的外部编辑，不是授权边界；冲突保留草稿并展示差异。通用保存可以写入任何受管文件，与在工作台以外直接编辑相同。修复核验另有表单，执行需要运行的步骤并写入结果。

首次打开或初次加载 Markdown 不保存，也不归一化原文；编辑器不认识的语法保留源码。

导航提交前保存唯一活动编辑器的最新草稿。保存失败时留在当前 URL，用户可以继续编辑或明确丢弃。设置页的非法 JSON 不因切换表单与 JSON 表示而丢失，确认丢弃后也不会迟到写入。连续导航时只有最后一个仍有效的目标生效。

## 工作区状态

导航读取服务端维护的工作区投影（[CLI 字段](cli.md#工作区投影)），请求本身不扫描来源。投影与读取的状态这样呈现：

| 情形 | 页面呈现 |
| --- | --- |
| 已有结果，扫描期间某个文件变化 | 立即显示旧结果与构建时间，后台继续刷新，不显示失败；导航不返回 409，下一次成功刷新替换它 |
| 尚无结果，来源持续变化（包括每 5 秒一次的自动保存） | 显示构建中，每两秒重试；第一次一致的刷新完成前不显示导航；来源停止变化后一次刷新即可完成 |
| 编辑了 `concord.config.ts` | 不再显示旧配置的结果，先显示构建中 |
| 缓存损坏或原生模块不可用 | 显示具名的不可用原因与恢复动作，不回退成同步扫描 |
| 无缓存或已有结果时遇到 RecoveryRequired | 显示具名阻断与恢复入口；恢复成功后立即申请刷新 |
| 发布租约被占用 | 最多异步等待三秒，超时后显示可手动重试的错误，不叠加浏览器自动重试；活跃持有者不因等待超时被清除 |
| 读取文件遇到短暂的 RepositoryBusy | 有限次重试；持续冲突时提供手动重试，切换文件取消旧请求 |
| 工作台首次读取失败 | 服务端记录错误码与响应状态。持续占锁时，错误页可显式恢复已退出进程留下的发布锁；仍在运行的持有者被拒绝；恢复成功后重新读取工作区投影 |
| 一个 owner 损坏 | 其它正常记录照常显示；无法推断的身份或历史只显示原文诊断 |

来源漂移由后台继续刷新，普通页面不显示漂移警告与变化路径。扫描完整性与未知关系留在「工作区健康」中显示，不伪装成健康。来源一致但扫描不完整、刷新失败与恢复阻断时，页面显示可关闭的诊断提示。关闭只隐藏当前这组问题，不改变诊断或完整性；问题变化，或恢复健康后再次异常时，重新提醒。

新结果与任务状态变化在一秒内到达已打开的页面，不等待轮询；事件连接断开时回到轮询并自动重连。

## 验收

视觉验收使用真实浏览器截图和计算样式，不只检查变量声明。`pnpm gate` 验证构建、类型和打包消费者行为，不能替代视觉验收。

- 数据量：无数据、单条、18 条以上记录。
