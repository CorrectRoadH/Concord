# 在 Markdown 中运行 p5 交互图解

## 用户目标

维护者想在文档里放一段会动的图解：用 p5 sketch 展示一个过程的动画、模拟或可操作的解释，读者打开页面就能看到，不需要另装工具。静态结构仍用 Mermaid。

## 起始状态

- 项目已初始化，`concord view` 正在运行，浏览器打开了它显示的地址。
- 要写图解的 Markdown 位于 `docs/` 下，例如 `docs/guides/flow.md`。

## 完整路径

### 内联与文件引用

1. 在 Markdown 里写一个 p5 图块。 {#write}

   小型图解直接写在 `p5` 围栏内，正文里可以直接使用 `p`。讲解流程时，推荐让动画自动循环：按顺序突出当前阶段，完成后短暂停留，再回到起点。

   ````markdown
   # 检查流程

   ```p5
   const stages = ['读取事实', '验证关系', '生成视图'];
   let elapsed = 0;
   p.setup = () => {
     p.createCanvas(540, 160);
     p.describe('读取事实、验证关系、生成视图按顺序自动循环');
     p.textAlign(p.CENTER, p.CENTER);
     p.textSize(16);
   };
   p.draw = () => {
     elapsed = (elapsed + Math.min(p.deltaTime, 100)) % 6000;
     const step = Math.floor(elapsed / 2000);
     p.background(245);
     stages.forEach((label, i) => {
       p.fill(i === step ? '#d8eee7' : '#ffffff');
       p.rect(20 + i * 180, 45, 140, 60, 8);
       p.fill('#203b33');
       p.text(label, 90 + i * 180, 75);
     });
   };
   ```
   ````

   图解较大时，把源码放进仓库里的文件，再用 `` ```p5 src="./queue/main.ts" `` 引用它。内联写法、文件入口、全局模式与路径规则见 [p5 图块格式](../format.md#p5-图块)。

   写动画的建议：

   - 每轮只解释一个过程，阶段名称和简短说明跟着动画走，读者不用操作就能看完。
   - 直接用 `p.draw` 驱动流程，不加播放、暂停、上一步、下一步或重置按钮。只有读者需要调参数或操作模拟时才加控件。这是表达建议，不限制 p5 API。
   - 按绘制时间累计进度时，像上例的 `Math.min(p.deltaTime, 100)` 一样限制单帧的时间增量，避免页面恢复可见后一下跳过好几个阶段。
   - 动画只解释 Spec 声明的过程，演示里的成功状态不是实际执行或验收的证据。归属、目录结构等不需要时间顺序的关系用静态图。

### 执行与生命周期

2. 在工作台打开这篇文档，图解自动运行。 {#run}

   在「文档」里点「检查流程」，或直接打开 `/docs?file=docs%2Fguides%2Fflow.md`。标题「检查流程」下是一块画布，三个阶段框依次高亮、循环播放；画布下方是折叠的「编辑 p5 源码与引用」。

   图块像动画图片一样直接播放，不需要点编译或播放，正常展示时也没有运行工具栏。阅读页与编辑页使用同一个运行环境。

   - 画布滚出视口或页面隐藏时暂停绘制，回到可见时继续。暂停只控制 p5 的绘制循环，sketch 自己调用过的 `noLoop()` 保持有效。额外创建的实例和非绘制计时器由作者自己管理。
   - 展开「编辑 p5 源码与引用」修改源码或选项，短暂防抖后自动加载最新输入。修改源码或选项、切换文档时，旧的沙箱被销毁。
   - 重新打开或刷新文档时重新读取外部依赖。
   - 自动加载、展开源码、重试、下载与主题变化都不保存 Markdown。显式的源码或选项编辑走工作台的[自动保存](../ui.md#自动保存)与摘要冲突保护。引用外部文件不复制源文件内容，也不新增写入入口。

### 主题色

3. 让图解跟随工作台主题。 {#theme}

   在 sketch 里读取 `--concord-bg`、`--concord-accent` 等[主题变量](../format.md#主题变量)，而不是写死颜色。点击右上角的主题切换按钮后，图块与同页 Mermaid 图一起换色：每帧读取变量的 sketch 下一帧就换色，不会重启。

### 扩展与排错

4. 需要时加入控件、资源与扩展库。 {#extend}

   让读者操作的模拟可以创建自己的 DOM 控件，用 CSS 排版；图片、字体等资源用相对模块导入。需要 `p5.sound` 等扩展库时，在 `concord.config.ts` 中声明，所有图块都会加载：

   ```ts
   p5: {
     libraries: ['p5.sound'],
   },
   ```

   资源与扩展库的规则见 [p5 图块格式](../format.md#样式与资源)。

5. 修正运行失败的图块。 {#diagnose}

   源码有错时，图块显示具名诊断与重试入口，原文保留。例如少写了右括号：

   ```text
   坏图
   运行失败重试
   P5CompileFailed: Build failed with 1 error:
   sketch:docs/guides/__inline_p5__.ts:4:1: ERROR: Unexpected end of file
   ▸ 编辑 p5 源码与引用
   ```

   改正源码后，图块自动重新加载。

## 结果

文档里的图解在工作台的阅读页与编辑页中直接运行，运行不改动 Markdown 的任何字节。

| 情形 | 看到什么 |
| --- | --- |
| 普通代码块、HTML 或 MDX | 只显示源码，不执行脚本 |
| 同一页面有多个图块 | 每个图块在自己的沙箱中运行，互不影响 |
| 语法、类型、路径、依赖或预算错误 | 图块显示具名诊断与重试入口，不替换成一张成功画布，原文保留 |
| 外部依赖在编译期间被改写 | 返回 `P5SourceChanged` |
| 引用了仓库外、symlink、隐藏路径、未知扩展库或远程 import | 拒绝并显示诊断，编译不执行作者代码 |
| sketch 尝试联网、访问父页面或申请设备权限 | 被运行环境阻断，见[运行环境](../format.md#运行环境) |
| sketch 同步死循环 | 浏览器可能失去响应；超时诊断只说明启动没有完成 |
| 首次打开工作台 | 首屏不加载 p5 运行库，打开含图块的文档时才加载 |

p5 运行时与内建扩展随归档离线可用。验收在真实 Chromium 中观察内联实例模式、完整默认导出模块、全局模式与外部多文件入口，以及 2D、WebGL、DOM 控件、事件、CSS 和本地资源；还要观察自动启动、视口暂停与恢复、多实例隔离、修改与离页清理。编辑页与只读页都识别 p5 图块及其选项，Mermaid 的行为保持不变。最后通过打包后的公开 CLI 启动一个隔离的 Git 消费者，验证动画、扩展与安全边界，不依赖开发仓库或全局安装。
