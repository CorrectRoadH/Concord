# 在工作台浏览并编辑项目文档

## 用户目标

维护者想在浏览器里找到项目里的 Spec 与文档，直接编辑正文，并确信编辑不会覆盖别人同时做的修改。

## 起始状态

- 项目是一个已用 `concord init` 初始化的 Git 工作区，例如有 Feature `docs/feature/cart/`。
- 维护者在仓库目录里有一个终端，并能在本机打开浏览器。

## 完整路径 {#主流程}

1. 启动工作台。 {#start}

   ```sh
   concord view
   ```

   ```text
   Concord view
   Root: /home/me/shop
   Host: 127.0.0.1  Port: 4317

     Local:   http://127.0.0.1:4317/
   ```

   命令保持运行，按 Ctrl-C 停止。默认只监听本机回环地址；要让其它机器访问，显式传入 `--host` 与 `--port`，启动输出的字段见 [CLI 与 Web 操作对应](../cli.md)。

2. 打开地址，找到要维护的对象。 {#navigate}

   浏览器先进入「Git 变更」，见[查看本地未提交变更](review-local-changes.md)。左侧主侧栏是分类入口：

   ```text
   工作区
   Git 变更  总览  文档  写作  术语
   Feature  Engineering  Roadmap  Design  Memory  反馈
   诊断与工具  项目设置
   ```

   点「Feature」，内容导航列出全部 Feature 与筛选框，右侧预览第一项；点「cart」只切换右侧预览。Feature 的页签是「正文、Use Cases、术语、实现、测试、元数据」。在「Use Cases」页签点一个 Use Case，它从右侧的详情抽屉打开，Feature 留在背景里。

   架构、品味、概念、指南与参考模板这类不属于任何分类的 Markdown，在「文档」里打开：

   ```text
   项目文档
   Project documentation
   Project architecture
   Project taste
   Project concepts
   …
   参考模板
   ▸ design  ▸ engineering  ▸ feature-design  …
   ```

3. 编辑正文。 {#edit}

   在正文最后一段「购物车可以一次结算全部商品。」后面输入「网页里写的一句话。」。停止输入后，标题旁的状态从「等待自动保存…」变为「已自动保存」，文件已写入工作树：

   ```sh
   tail -n 1 docs/feature/cart/README.md
   ```

   ```text
   购物车可以一次结算全部商品。网页里写的一句话。
   ```

   保存只写工作树，不暂存、不提交。保存时机与规则见[自动保存](../ui.md#自动保存)。

4. 跟随正文里的链接。 {#follow-link}

   点击正文中指向其它文档的相对链接，工作台先完成待保存的草稿，再在页面内打开目标文档；指向外部网站的链接由浏览器打开。链接解析规则见 [Markdown 呈现](../ui.md#markdown-呈现)。

5. 处理别人同时做的修改。 {#conflict}

   你正在编辑时，另一个人或 agent 在工作台以外改了同一个文件。下一次自动保存因摘要不同被拒绝，草稿保留：

   ```text
   外部变更
   自动保存失败  重试保存
   当前草稿没有被覆盖。请比较后保留草稿或重新载入。
   比较未保存草稿
   左侧是你的草稿，右侧是当前磁盘版本。重新载入会明确丢弃草稿。
   继续编辑草稿   丢弃草稿并载入
   ```

   对照磁盘版本合并后选「继续编辑草稿」再保存，或选「丢弃草稿并载入」采用磁盘版本。

6. 新建 Spec。 {#create}

   在内容导航标题旁点「新建 Feature」等按钮，填写表单创建。Use Case 在所属 Feature 的「Use Cases」页签里点「新建 Use Case」创建，会自动绑定这个 Feature。

## 结果

仓库里的文件始终是事实来源：工作台读写的就是 `docs/` 与 `memory/` 下的文件，关系从源码与文档推导。

| 情形 | 看到什么 |
| --- | --- |
| 首次打开一篇 Markdown | 不保存，也不归一化原文；编辑器不认识的语法保留源码 |
| 带 frontmatter、frontmatter 无法解析、自定义中文路径或嵌套页面 | 都可以编辑，没有只读白名单；解析失败的文件在原文编辑器中修复 |
| 清空正文后保存 | 文件被清空，按整文件摘要写入 |
| 编辑 `docs/taste.md` | 在「文档」中使用同一个原文编辑器 |
| 未保存的草稿与 Git 改动 | 草稿对比在编辑器里，与「Git 变更」中的差异分开显示 |
| 外部修改与保存冲突 | 拒绝保存，保留草稿，不覆盖外部编辑 |
| 用深链接打开，例如 `/docs?file=docs%2Ftaste.md` | 直接打开该文档；刷新后保持当前位置 |
| `concord.config.ts` 无法读取 | 设置页显示服务端安全读取的原文与诊断；无法安全读取原文时明确说明。不读取旧文件，不吞掉失败，也不把权限、迁移或格式错误显示成待初始化 |
| 工作区还在构建、刷新失败或需要恢复 | 见[工作区状态](../ui.md#工作区状态) |
| 显式传入 `--host` 开放监听 | 能连接端口的人都可以读写仓库、运行配置的测试命令；Host/Origin 检查见[本地服务信任边界](../architecture.md) |

### 验收

工作区状态各行见[工作区状态](../ui.md#工作区状态)，视觉要求见[界面验收](../ui.md#验收)。静态资源包含在归档内。阅读与结构检查都不是合规证据。
