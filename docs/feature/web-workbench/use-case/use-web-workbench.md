# 浏览、编辑并检查项目变化

维护者启动 `concord view`，直接打开终端显示的地址，在同一工作台维护契约、实现关联和验证状态。

## 主流程

1. 从侧栏进入 Feature、Engineering、Roadmap 等对应列表，或从「文档」打开 `docs/` 下没有分类 owner 的项目文档；Use Case 在所属 Feature 内维护。
2. 创建契约，使用富文本编辑正文，检查关联代码与测试。保存需要当前文件摘要，外部修改发生时保留草稿并显示冲突。
3. 在 Git 面板分别检查未暂存、已暂存与未跟踪文件。统一或分栏差异明确比较基准；Markdown 编辑器未保存差异与 Git 差异分开呈现。
4. 选择已声明测试运行，观察结果，必要时取消。完成进程组清理后才能释放仓库锁并运行下一个任务。
5. 通过表单执行 Memory、Issue、Design、Roadmap 生命周期，使用原有证据门禁；Web 不接受调用方伪造的修复证明。

## 验收

- 静态资源包含在安装包内，浏览器深链接可直接打开；默认监听 0.0.0.0，所有数据 API 必须认证且检查 Host/Origin。
- Markdown 初次加载不自动保存或归一化原文件；未知语法保留源码，冲突不覆盖草稿。
- Markdown 正文中的相对链接以当前文件为基准解析；目录链接落到该目录的 `README.md`，已纳入工作区的文档和支持页面使用内部导航，并在切换前完成待保存草稿。外部 URL 保持浏览器导航，越界或未知目标不伪装成工作区页面。
- 代码块保持等宽字体与原始行，不自动折行；长行在块内横向滚动，包含 Mermaid 源码。显示、主题和滚动变化不改写 Markdown 字节。
- 文件读取遇到短暂 RepositoryBusy 时有限重试；持续冲突提供手动重试，切换文件取消旧请求。
- 文件树同层文件夹与文件的图标和文字对齐，文件夹优先，同层按名称排序。
- Git 正确处理暂存后再编辑、重命名、删除、二进制和特殊文件名；符号链接预览不读取外部目标。
- 空闲服务不占用仓库锁；运行中能查询和取消，取消后可再次成功运行。未确认清理时明确阻断操作。
- 源码编辑限定配置范围内既有 JS/TS 文件，带摘要保护及恢复日志；文档与源码使用一套当前日志格式，严格检查各自写入范围。
- 一个损坏 owner 不隐藏其他正常记录；不可推断的身份或历史只显示原文诊断。
- Git 状态读取只加载当前配置与 Git 数据，不触发完整工作区扫描；单个支持页面保存只检查目标与归属链，继续遵守摘要、只读来源和恢复保护。
- Feature 的 Use Cases 有独立页签，列表与创建入口不放在正文下方；打开子项显示详情抽屉，关闭返回 Use Cases 页签。
- 慢请求不产生重叠轮询；缓存命中仍能识别外部同长度改写、删除以及 HEAD 变化。单文件读取不枚举全仓库，同时保留目标路径和归属链校验。
- Research 主题内切换文件保留树的折叠和滚动状态；正文已滚动、长短文件互切时，加载中与加载后的工具栏和文件树也保持位置稳定。

- 已配置中立测试套件时，展示通过 Feature / Use Case 路径关联的测试；不要求 executor/lanes，不加载 host 或执行测试。列表展示失败诊断，并保留通用 runner 的授权范围。

- 实现页按 Feature 和 Use Case 分组展示明确的代码声明，支持一对多与多对多关系；点击定位到源码范围，顶部统一添加关联并选择目标契约；分组直接显示功能名称，以紧凑源码列表和分隔线组织，不添加类型前缀或嵌套卡片。没有声明时引导接入，不以测试文件代替实现。
- Feature 与 Use Case 使用「正文、术语、实现、测试、元数据」组织维护任务，Feature 另有 Use Cases 页签。只有 Roadmap、Design、Memory、Issue 显示生命周期入口；没有状态转换的类型将旧 `?tab=actions` 入口回落到元数据。身份、ID、创建时间归入元数据；生命周期展示状态、实际可用操作和历史，不渲染空操作面板。
- 文档集合的新建入口归属于内容导航，在桌面侧栏和移动内容导航工具栏提供；详情工具栏只放当前对象操作。切换页签、新建和详情导航继续遵守草稿保存与冲突保护。
- 配置无法读取时展示服务端安全读取的 `concord.config.ts` 原文及诊断；无法安全读取原文时明确说明，不尝试读取旧文件、不吞掉失败，也不把权限、迁移或格式错误显示成待初始化。
- 反馈条目采用共享内容导航，证据采用共享记录列表；元数据和设置采用自然高度的字段分组与统一保存状态。空集合、筛选无结果、对象不存在分别表达，不以大虚线框和搜索失败图标统一代替。
- 实现位置和测试声明都是可检查入口；点击后以 URL 中的源码路径及行范围打开右侧抽屉。关闭抽屉回到所属文档的原 tab/file，不重新挂载外层契约。实现源码沿用受管编辑入口，测试源码只读。
- 各页面的 tab、当前文件、Use Case 与源码抽屉、Git 展示模式直接从 URL 派生，不保存本地导航副本。前进、后退、刷新和直接打开均恢复对应位置；缺省或无效选择按页面能力回落。
- 导航提交前保存唯一活动编辑器的最新草稿；失败留在当前 URL，用户可以继续编辑或明确丢弃。设置页的非法 JSON 不因切换表示而丢失，也不在确认丢弃后迟到写入。连续导航只允许最后仍有效的目标推进。
- 源码抽屉在桌面保持适合阅读的宽度、在移动端占满屏幕，只展示一次文件路径，按真实行位置滚动到声明起始行并突出该行；源码带行号与适应明暗主题的语法高亮，长行横向滚动。查看和定位不修改文件。Feature、Use Case 与 Engineering 的实现列表直接展示符号、范围、源码位置和关联契约，不折叠声明详情，不显示或要求填写声明 ID；宽内容区分列，窄内容区自然堆叠。添加关联只选择 scope 和契约，生成可粘贴的无 ID 注释。
- 术语来自当前文档目录有效的 `concepts.json` 定义，由后端合成全局、祖先和显式直接导入，显示完整来源与诊断；Markdown 不作为结构化定义来源。测试只来自用户写入源码的 Feature / Use Case 关联声明。Web 将不同接入投影统一显示为「测试」，不要求用户理解 Repository 测试或通用 runner 等内部来源。
- 「文档」列出 `docs/` 下不属于分类 owner 或 Memory 来源的 Markdown。深链接 `?file=` 可直接打开架构、宪法和参考模板。宪法可从文档页进入正文编辑，采用或修订通过既有专用操作保存，填写原因、影响及可选来源，不通过普通文档保存入口重写历史。未授权路径仍只读；已授权且无 frontmatter 的项目文档沿用普通编辑。阅读不是合规证据。
- 参考模板按物理目录展示可折叠树，叶子显示文件名；搜索标题或路径时保留祖先层级并展开结果。深链接、刷新及前进后退展开当前文件的祖先，文件选择继续由 URL 决定。桌面与手机导航提供相同文件集合和键盘可用的折叠按钮。
- 阅读视图正确处理 YAML frontmatter 与 HTML 条款锚点，元数据和原文可单独展开；不因 WYSIWYG 不支持 HTML 而显示编辑失败。阅读时不得写文件、执行嵌入脚本或事件属性；保留条款链接定位和相对文档导航。

- 文档、写作、术语、反馈、Git 的对象选择复用同一内容导航。桌面列表常驻，手机选择后关闭内容抽屉。写作首先选择适用范围；反馈切换保留保存保护；Git 保留目录展开、状态、分类、区域与新增测试行定位。列表切换只改变右侧对象，不触发运行、同步或提交。
