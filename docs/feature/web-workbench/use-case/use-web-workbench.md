# 浏览、编辑并检查项目变化

维护者启动 `concord view`，直接打开终端显示的地址，在同一工作台维护契约、实现关联和验证状态。

## 主流程

1. 从侧栏进入 Feature、Engineering、Roadmap 等对应列表；Use Case 在所属 Feature 内维护。
2. 创建契约，使用富文本编辑正文，检查关联代码与测试。保存需要当前文件摘要，外部修改发生时保留草稿并显示冲突。
3. 在 Git 面板分别检查未暂存、已暂存与未跟踪文件。统一或分栏差异明确比较基准；Markdown 编辑器未保存差异与 Git 差异分开呈现。
4. 选择已声明测试运行，观察结果，必要时取消。完成进程组清理后才能释放仓库锁并运行下一个任务。
5. 通过表单执行 Memory、Issue、Design、Roadmap 生命周期，使用原有证据门禁；Web 不接受调用方伪造的修复证明。

## 验收

- 静态资源包含在安装包内，浏览器深链接可直接打开；默认监听 0.0.0.0，所有数据 API 必须认证且检查 Host/Origin。
- Markdown 初次加载不自动保存或归一化原文件；未知语法保留源码，冲突不覆盖草稿。
- Git 正确处理暂存后再编辑、重命名、删除、二进制和特殊文件名；符号链接预览不读取外部目标。
- 空闲服务不占用仓库锁；运行中能查询和取消，取消后可再次成功运行。未确认清理时明确阻断操作。
- 源码编辑限定配置范围内既有 JS/TS 文件，带摘要保护及恢复日志；文档与源码使用一套当前日志格式，严格检查各自写入范围。
- 一个损坏 owner 不隐藏其他正常记录；不可推断的身份或历史只显示原文诊断。
