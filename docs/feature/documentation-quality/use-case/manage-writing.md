# 在 Web 管理写作规则与术语

维护者在「写作与术语」选择全局或局部目录，分别编辑本目录政策和概念。全项目汇总与继承定义只读，显示定义来源和作用域；新建局部来源通过受管 API 验证路径。

## 主流程

1. 发现来源并选择目录；缺失、有效、无效各自呈现。无效原文和摘要保留用于明确修复，不隐藏失败。
2. 编辑禁用表达、替换建议、理由及适用范围，或编辑概念 ID、定义、语言名称、允许别名、弃用名称及显式引用。
3. 每个 owner 显式保存并使用自己的原始摘要。冲突保留草稿；一份保存成功不能清除另一份未保存内容。
4. 查看来源标注的聚合定义与歧义。引用沿原定义身份解析，不创建第二份术语登记表。
5. 按需检查已保存内容，报告说明实际模式、根集合和输入快照；不把草稿或历史结果称为当前通过。

## 验收

路径选择、草稿、基线和异步响应绑定 kind 与 canonicalPath。A 切换到 B 后迟到的 A 响应不得覆盖 B。切换/离开遵守脏草稿保护，不触发隐藏自动保存。保存后的刷新不能拿另一写者的 digest 作为旧草稿基线。

CLI action 与 Web 共用严格解码、作用域编译、摘要和恢复授权；只允许 docs 下精确受管文件名，不提供任意 JSON 写入口。非法局部 roots、悬空引用、空字段、重复身份或危险路径被服务端拒绝。

真实浏览器覆盖政策与概念创建/修改/删除条目、来源筛选、全局汇总、继承只读、部分保存冲突、切换竞态及继承目录的外部修改。恢复、输入快照、显式迁移和语料范围遵守目录作用域采用方案。检查不能冒充执行证据。
