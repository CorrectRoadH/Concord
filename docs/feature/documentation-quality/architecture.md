# 文档写作检查的实现

行为见 [README](README.md) 与[文件格式](format.md)；本页只声明实现边界。

## 事实归属

| 实体 | 归属 |
| --- | --- |
| 术语定义与旧写法 | 所在目录的 `concepts.md` |
| 长度上限、不用的词与检查范围 | 所在目录的 `writing.md` |
| 合成后的有效规则 | 每次检查从文件派生，不持久保存 |
| 编译后的匹配器 | 进程内按有效规则的摘要复用 |
| 写作 findings 缓存 | HawDB `query_cache` 中 `writing:` 命名空间的可丢弃派生值 |

## 数据流

1. 在同一仓库快照中读取全部 `writing.md`、`concepts.md` 与选中的 Markdown，按[文件格式](format.md)解析。
2. 按每个文件所在目录合成有效规则。
3. 剔除步骤标记后逐块分句、计数、匹配；finding 保留原始位置、实际计数、上限与来源。
4. 复核全部输入的字节与成员，变化时返回 `SourceChanged`，不发布陈旧结果。

输入摘要包含全部规则与术语文件的原文、文档成员与字节，以及解析器版本标识。解析语义改变时更新版本标识，使旧缓存失效。

## 不变量

1. 缓存只省略重复的文本分析。命中前仍读取来源，返回前仍复核来源字节和成员；摘要不匹配、记录损坏或缓存不可用时重新计算。
2. 缓存记录最多 10000 项 findings，单项不超过 8 MiB，与同一命名空间共享 64 项、16 MiB 配额。
3. 编辑器中未保存的文本不进入缓存。
4. 写作检查不启动 adapter、LSP 或其它外部进程。
