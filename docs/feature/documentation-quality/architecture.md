# 文档写作检查的实现

行为见 [README](README.md) 与[文件格式](format.md)；本页只声明实现边界。

## 事实归属

| 实体 | 归属 |
| --- | --- |
| 术语定义与旧写法 | 所在目录的 `concepts.md` |
| 长度上限、不用的词与检查范围 | 所在目录的 `writing.md` |
| 合成后的有效规则 | 每次检查从文件派生，不持久保存 |
| 编译后的匹配器 | 进程内按有效规则的摘要复用 |
| 写作 findings 缓存 | HawDB `query_cache` 中 `writing:` 命名空间的可丢弃派生值 |

## 数据流

1. 工作区服务在增量工作区图中维护全部 `writing.md`、`concepts.md` 与受检 Markdown 的解析树。
2. 按每个文件所在目录合成有效规则，编译后的匹配器按有效规则摘要在内存中复用。
3. 文件未发生 `(mtime, size, inode)` 且所属目录规则未变时，直接复用该文件的写作 findings；文件或规则变化时，仅对该文件剔除步骤标记后逐块分句、计数、匹配，并更新工作区图与持久缓存。

## 不变量

1. 缓存按文件 `(mtime, size, inode)`、内容摘要、有效规则摘要与解析器版本标识增量失效；记录损坏或缓存不可用时重新计算。
2. 缓存记录最多 10000 项 findings，单项不超过 8 MiB，与同一命名空间共享 64 项、16 MiB 配额。
3. 编辑器中未保存的 overlay 文本在内存中即时计算，不写入持久缓存。
4. 写作检查不启动 adapter、外部 LSP 或其它子进程。
