# 测试执行与浏览器验收

本页遵守 [独立、本地、可安装](../../constitution.md#c-002)、[只声称证明过的](../../constitution.md#c-021)、[维护代码采用严格 TypeScript 与 Effect](../../constitution.md#c-005) 与 [用产品自身管理和验收开发](../../constitution.md#c-006)，规定测试如何执行；测试应当怎样写见[测试架构](test-architecture.md)。

## 执行入口

`pnpm check` 的测试阶段统一调度 Node 测试与 e2e 浏览器测试。两类测试运行本次调用构建的 `dist`。分片分别作用于两类测试，所有分片的并集覆盖完整集合。失败不能阻止另一类测试执行，任一失败使整体失败。

| 方面 | 规则 |
| --- | --- |
| Node 并发 | 默认按文件进程并发，数量为 `min(8, max(1, floor(可用 CPU / 2)))`；`CONCORD_TEST_CONCURRENCY` 显式覆盖，必须为正整数 |
| e2e 并发 | 默认 worker 数为 `min(4, Node 并发)`；`CONCORD_E2E_WORKERS` 显式覆盖。每个用例使用自己的临时仓库与 View 地址 |
| 构建产物 | 测试以只读方式运行 `dist` 的入口，不打包、不安装、不复制；只有打包测试把 `dist` 打包并安装一次，验证发布内容与从安装包启动 |
| 私有副本 | 会修改或破坏产物文件的测试只把需要的文件复制到自己的临时目录，不改动 `dist` |
| 并发隔离 | 测试拥有各自的临时目录、动态端口与进程组；依赖全局状态的用例在文件内串行，不降低全局并发 |

本地与 CI 使用相同的默认值。默认值改变时，用同一冻结快照按[统一方法](performance.md)测量前后两种设置。

`test/*.test.ts` 拥有领域、HTTP、生命周期与打包消费者测试，`test/e2e/*.e2e.ts` 拥有浏览器行为测试。Concord 的 testRoots 包含两者，测试标记随用例迁移。按文件执行与按标题过滤必须路由到相应 runner，不能将 e2e 文件交给 Node test。

## 共享资源与同步

并发执行只有在每个测试不改坏他人、也不被他人的负载误判时才可信。以下规则适用于测试、Fixture 与测试运行器调用的脚本。

| 方面 | 规则 |
| --- | --- |
| 替换文件 | 替换可能被其它进程打开或映射的文件（`.node`、安装目录中的 JS、缓存与锁之外的产物）时，先写同目录的新文件，再 rename 覆盖，不原地截断或改写。原地改写已映射的原生库会使正在运行的进程崩溃 |
| 破坏性操作 | 会损坏、删除或替换产物文件的测试与脚本使用私有副本；调用这类脚本的测试同样使用私有副本 |
| HTTP 客户端 | 测试中的请求默认每次使用新连接，不复用 keep-alive 连接；只有验证连接复用的测试显式复用。测试与服务进程的事件循环停顿可能超过服务端空闲超时，复用的连接会在请求时被重置 |
| 等待 | 断言等待真实的产品状态：具体的请求与响应、投影代次或文件内容。固定时长只是等待上限，不代表异步链条已完成；不以延长超时、重试整段操作或 mock 成功响应代替同步 |
| 负载 | 同一台机器同时只运行一次完整门禁。失败报告记录运行时的 load average 与并发运行的其它门禁；在过载下出现的超时与连接重置，须在空闲机器上复跑后才能归因 |
| 诊断 | reporter 与诊断代码不得因测试产生的异常对象（循环引用、超大输出）而失败，原始失败事件仍交给 runner。子进程断言输出 exit code、signal、耗时与截断后的 stdout/stderr，以区分「输出已完整但未退出」与「没有输出」 |

## 浏览器与诊断

浏览器由 e2e Web engine 拥有，每次尝试使用独立 context。精确时钟、网络边界和 DOM 检查通过 engine 的公开 `surfaceOf` 访问当前 Page；浏览器只由 engine 关闭。测试拥有其临时 Git 仓库与 View 服务，在 finally 中关闭服务后删除仓库。测试服务停止时回收包含浏览器预连接在内的 HTTP 连接，保留页面供 runner 截图。成功、断言失败与超时均须进入资源回收。

确定性测试不配置模型，不需要凭据，不发出付费模型调用。重试和结果缓存关闭。失败保留 trace、截图与 runner 报告，CI 按分片上传产物。诊断不得依赖测试通过之后才能执行的代码。系统 Chromium 适配须有启动超时、取消响应、退出等待与强制终止后备路径；启动失败也须回收临时 profile。

## 自然语言适用范围

自然语言用例表达用户目标，精确断言判断结果。适合的操作包括创建 Unicode Feature 与 Use Case、打开和刷新深链接、切换文档、删除本地草稿，以及从健康提示进入诊断。文件持久化、准确路由、删除范围和草稿保护仍由确定性断言验证。

请求计数、CAS 冲突、乱序响应、时钟推进、CSS 几何、剪贴板权限和沙箱边界使用确定性测试。自然语言不负责推断请求顺序、等待固定时间或判断精确像素。

标有 `journey` 的用例共用 fixture 与精确断言。普通门禁执行确定性操作，`test:e2e:agent` 只选择这些用例并使用 `agent.act` 完成用户操作，不复制第二份场景与结果断言。模型配置只从 `E2E_MODEL_API_KEY`、`E2E_MODEL_BASE_URL`、`E2E_MODEL` 读取，执行须获得付费调用授权；每次操作有模型调用与步数上限，禁止缓存替代实际执行。

| 用例 | 自然语言操作 | 始终保留的精确检查 |
| --- | --- | --- |
| Unicode Feature / Use Case | 创建 Spec 并打开详情 | 编码路由、刷新恢复、文件中的 Unicode ID |
| Memory 与本地草稿 | 桌面和移动导航、确认删除草稿 | 当前选择、正文、索引中不存在已删除草稿 |
| 工作区健康提示 | 打开诊断并关闭提示条 | URL anchor、具体错误文件、提示消失后诊断仍存在 |

新流程实际覆盖旧用例的行为与关键断言后，删除对应旧用例；部分覆盖只移除已覆盖部分。迁移不能以未执行的自然语言用例替代完整门禁中的回归保障。
