# 审阅 agent 指南

## 用户目标

维护者修改 skill、模板或初始化说明后，要确认不同入口给出一致且适用于接入项目的指导，并能区分资源交付成功与 agent 的任务完成质量。

## 起始状态

- 修改范围及其所属 Spec 已明确。
- 有当前指南、随包文档、模板和初始化说明可供比较。
- 涉及模型执行时，运行环境与调用已经获授权；否则只进行静态审阅。

## 完整路径

1. 按实际入口读取资料。 {#read}

   读取 `concord --skill`、相关主题与生成的 `docs/concord.md`。从接入项目目录读取 `--skill document`，取得文档模型与完整示例；不得依赖 Concord 开发 checkout 的文件位置。

2. 用相同任务检查不同入口给出的决策。 {#scenarios}

   | 请求与已有材料 | 应得到的决策或产物 | 不合格的结果 |
   | --- | --- | --- |
   | 已有 Web 阅读界面，只补继续阅读的 Spec | README 从书库入口开始，Use Case 写恢复位置，按需补 UI 与架构页 | 管理员命令替代读者上手；修改业务源码、测试或配置 |
   | 补写途中要求设计后台阅读回顾 | 调查相关现状，写新增目标及验收，保留明确范围 | 等整仓补写或关联全部完成后才处理新需求 |
   | Go 服务已有性能测试，只补性能 Spec | 声明操作、负载、环境、指标与阈值，链接项目自己的测量方法 | 强制新增 TypeScript 基准、采用固定 p50 或 Bun |
   | 已授权修复一个缺陷，无需留待处理 | 读取 fix 指南，选择当前核验路径，保留核验边界 | 强制创建 Issue 或把已关闭的核验结果写回 Issue 文件 |
   | 本次文档检查发现其它功能的旧问题 | 处理本次引入项和必要依赖，报告其它问题 | 为消除全部 finding 扩写无关功能 |
   | 调查产生复用经验和一段执行日志 | 经验有适用条件与证据；执行日志留在交付中 | 把流水账或验收进度作为 Memory |

3. 检查结果的语义。 {#inspect}

   静态审阅对照每个场景的输入与指导，找出缺失资料、矛盾或越界要求。实际执行评估时，从相同的隔离 fixture 出发，保留请求、指南版本、agent 回复、命令与最终 diff；检查每一步是否服务用户目标，以及修改范围是否符合授权。

   代表性成稿见 [Spec 写作示例](../../../guides/spec-examples.md)。示例只能作为比较材料，不能把预写的期望文档冒充 agent 实际输出。

4. 分别交付两类结论。 {#report}

   资源测试证明命令在安装边界输出正确资料，并在资源损坏时具名失败。任务评估报告实际产物、问题位置与未运行的场景；未调用模型时明确写“静态审阅”，不声称验证了 agent 的行为。

## 结果

指南的每个入口都有可取得的资料，任务范围与页面归属一致。发布说明分别报告结构检查和任务评估；不以字符串匹配、退出码或模型完成通知代替产物审阅（[只声称证明过的](../../../taste.md#t-5)）。
