# 开始写 Spec

仓库刚接入 Concord，维护者请你开始写第一批 Spec。先确认从哪里写起，再读对应的写作指南。

## 1. 问维护者从哪里写起

先看一眼仓库：有没有源码、测试、构建文件和旧文档。然后问维护者选哪条路，把看到的情况作为建议一起说出来，由维护者决定：

| 路径 | 适合 | 写作指南 |
| --- | --- | --- |
| 从零写 | 还没有代码，或打算推倒重写；先写目标和行为，再按 Spec 实现 | `concord --skill docs-from-scratch` |
| 为已有代码补写 | 代码已经在用；先让 Spec 准确描述它现在做什么 | `concord --skill docs-from-code` |

例如：

```text
仓库里有 src/ 和 package.json，还有 40 个测试，看起来已经有代码在用。
要我先为现有代码补写 Spec，还是从零写一份新项目的 Spec？
```

已有代码、又要做大改动时，先为已有代码补写现状，再按 `concord --skill spec` 写改动。维护者回答之前不创建文档。

## 2. 读指南并照着写

运行维护者选定的那份指南，按它的顺序写。每写完一批运行 `concord check`，逐个处理具名 finding；写到一半换路径时，直接读另一份指南，不需要重新初始化。
