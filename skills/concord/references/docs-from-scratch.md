# 从零写 Spec

从明确的用户目标建立 Spec。用户要求写文档时只写文档；同时授权实现时，完成相关 Spec 后再按 `concord --skill implement` 开发。

读项目说明与已有决策，沿用对话中明确的用户、问题和范围，只有关键歧义才询问。把项目用途写进 `docs/README.md`，相关领域名词定义在生效的 `concepts.md`，系统边界与组件职责写进 `docs/architecture.md`。品味只记录维护者采用的判断标准，不把具体实现机制提炼成通用偏好。

运行 `concord --skill document`，先看 docs 目录树，再读完整的 Feature、Use Case 与细节页示例。按本项目的目标组织内容，按需创建文件，不复制示例产品的能力或生成全部空页面。

先写最有代表性的一项能力：README 从主要使用者的入口讲上手，Use Case 写一条完整路径及可观察的结果，主流程步骤带 `{#id}`。未运行验证的结果标为预期结果。检查路径是否能走通、每一步是否服务同一个目标，再扩写。

按读者需要增加 UI、API、CLI、格式或架构页，定下实现所需的公共语义与验收方式，详见 `concord --skill spec`。已采用的目标归 Feature，尚未采用的方向归 Roadmap，真正未决的取舍归 Design。

交付前运行 `concord check`，修复 finding 并重跑至通过才完成；确实受环境、权限或文档写改范围阻塞时，明确报告未完成与所需条件；交付写作范围、关键决定、验收方式与待决定的问题。新功能的实现与测试关联跟随获授权的实现工作；本次删除或迁移页面不能留下失效的已有引用。
