# 已接受的 socket 断开后不能等待重新连接

通用 socket writer 在 reader 释放后可能等待下一次 reader 打开。工作区服务接受的单条连接没有重新连接的生命周期：服务暂停期间客户端握手超时退出，服务恢复后处理排队请求，迟到的响应可能进入这个等待。

RPC 的响应清理不可中断，退出流程等待它完成；因此仅对子进程提供 TERM/KILL 升级不能保证整个服务退出。计算子进程仍存活也不能直接证明卡在计算清理，RPC 清理可能先挡住后续资源释放。

服务端写出必须受真实连接的关闭事件约束：连接关闭后结束在途和迟到写出，不等待重连。关闭阶段写入运行记录，便于 socket 已失效时定位阻断；锁释放和 PID 退出仍分别核验。回归应暂停真实服务、让客户端超时断开、恢复服务后停止它，并检查子进程、socket、记录与重启取锁。
